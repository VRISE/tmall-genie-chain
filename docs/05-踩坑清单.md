## 怎么用这篇（先记三句话）

1. **先分「谁的锅」**：设备有没有开口 → 后端有没有收到 POST → 隧道有没有 `pxy/prv` → 才轮到怀疑自己的代码。这个顺序我反过一次，白改一整晚代码（2026-09-28）。
2. **「活着」这个词不许笼统用**。127.0.0.1 上端口开着 ≠ 隧道通 ≠ 平台拨得进来 ≠ 大模型能用。每层都要顺着打一遍、问一句（见 B2）。
3. **任何判据都要能指向「这一句、这一刻」**。数新增条数、看快照 json、看 `trainStatus`、拿 `/test` 的结果当真机 —— 我都踩过，每一条都亏过半天。

条目编号：A 平台/NLU，B 公网入口与隧道，C 后端代码与协议，D 大模型，E 设备与音箱，F 多会话并行。

## A｜天猫精灵平台与 NLU

**A1｜默认意图是被我自己一次 PUT 抹掉的，不是「训练还没好」**
- 现象：某一夜起，**所有**句子零 POST，连裸喊调用词都不回话；整条链像被人拔了电源。
- 误判：先怀疑隧道，再怀疑「训练要等 30~40 分钟」，最后开始改自己刚写好的路由代码 —— 顺序全反了。
- 真因：`PUT /api/skills/<sid>/intents/<iid>` 的 body 里没带 `defaultIntent:true`，意图被整份覆盖成非默认（GET 回来 `type:null`）。没有默认意图，平台就不把「不认识的话」往下兜，裸调用词也不再保证 POST。
- 结论：① 每次 PUT 意图必须带全字段，`defaultIntent:true` 写进 body，同时**删掉 `executeLogic`**（留着旧 `logicSetId` 直接 404）；② PUT 完立刻 GET 回来核对 `isDefault`；③ 判生效只看真机 `/log` 有没有那一句的 POST。
- 证据：2026-09-30 02:3x。同一轮还顺手纠正了「技能没发布所以在线测试回 `意图/null`」这条错觉 —— 跟发布无关，就是这条 + 必选参数两条。

**A2｜认证文件那道校验，个人技能是永远存不上的**
- 现象：控制台保存「服务部署」时红字 `retCode:3010 未正确获取到认证文件`；点「下载认证文件」回 `2002 没有访问资源的数据权限`，前端拼出来的 URL 里 `token=undefined`。
- 误判：以为是我 md5 算错、以为是 CSRF、以为入口藏得深没找到，在 UI 上耗掉半小时。
- 真因：校验文件必须是**公网域名根路径上能 200 拿到的 `md5(技能id).txt`**；而个人技能这条 UI 路本身是死的 —— `PUT /api/hybird/logicConfig` 一律 403，证书根本下载不到。
- 结论：别在 UI 上磨 —— 走**意图级 PUT 直接写 `webhook.url`**，运行时平台真的会拨（120282 就是这么活的）。另外 3010 和 CSRF 无关，真正要 `x-csrf-token: <ctoken>` 的是 `retCode:10031`。
- 证据：2026-09-30 00:3x（个人号连「无调用词应用」的入口都点不到，那条官方写明只对合作厂商开放 —— 我**没测过**，因为进不去）。

**A3｜「动态意图」那个开关决定平台理不理你**
- 现象：语料、实体、调用词全对，句子命中了，服务端一条请求都收不到，音箱自己回一句固定文案。
- 误判：怀疑穿透、怀疑语料写法、怀疑训练，半小时。
- 真因：意图没设成「动态」，平台压根不调 webhook。非动态 = 平台自己兜答。
- 结论：排查顺序钉死 —— **先看「动态」列有没有 ✓，再看「默认意图」是不是「是」，再看训练，最后才怀疑自己代码**。接口：`POST /api/skill/<sid>/intent/<iid>/toggleDynamic`。
- 证据：2026-09-28 凌晨，技能 113665，`play_video` 的 dynamic 一直是关的。

**A4｜ASR 把追问听成繁体，我的正则只写了简体 —— 整链哑**
- 现象：第二轮明明答得很清楚，后端一条 POST 都看不见；像平台不肯给第二轮。
- 误判：以为「SELECT 之后的第二轮不回后端」、以为开麦窗口过了。
- 真因：阿里 ASR 会吐繁体（`為您播放來自網民音樂獨家庫`、`企鹅`→`請餓`、`起鵝`），而我的命中表和校验只写了简体字，整句匹配又不做模糊 → 命中 0，看着像链路坏。
- 结论：① 繁简两套都收（或进表先归一）；② 听到外放幻觉词（`謝謝大家收看`、`字幕by索兰娅`）说明房间里有声音，**这一轮数据整条作废**，别拿它推任何结论。
- 证据：2026-09-29 ~ 09-30 多轮；`docs/_原始开发流水账.md` 09-30「第二跳依旧零 POST：候选『企鹅』被听成『請餓/起鵝』」。

**A5｜调用词会被官方节目抢走：技能名和调用词要分开挑**
- 现象：技能叫「猪八戒」，喊「天猫精灵，猪八戒，放XXX」，音箱直接播了一段评书，我们后端一条没收到。
- 误判：以为 NLU 抽风、以为实体没灌进去。
- 真因：**调用词是全平台唯一的、官方技能会抢同音/同名词**（个人号抢不到通用语句）；技能显示名和调用词是两回事，我一开始拿同一个词当两个用。
- 结论：调用词挑「三个音节、库里能秒答、不容易听歪」的词（我最后用「北极熊」这类）；改完用 `POST /api/skill?id=<技能id>` 读 `invocationName` 复核。换调用词约 4 分钟生效，**不需要训练**。
- 证据：2026-09-30 07:0x（网页 SUCCESS 的句子，方糖当场被酷狗音乐接走）；09-30 调用词一晚改了三版。

**A6｜只有灌进实体里的词能路由，「调用词 + 任意话」的尾巴会被 NLU 切掉**
- 现象：精心写的整句语料一句都不通，随便一句在实体里的却通；一直以为再补几条例句就能「想问什么问什么」。
- 误判：以为语料数量不够、以为训练没到位、以为私有技能更宽松。
- 真因：裸调用词一定 POST；但调用词后面那段自由话在 NLU 层被切，**只有能对上实体值的才落到我们的意图**。私有（113665）和公有（120248）同一分钟同批句子对打，行为一模一样，私有并不宽松。
- 结论：这条是死墙，别再找第三条。可抄的只有两条：枚举实体值（硬顶 10000 条）+ `SELECT` 当场报菜名；或者完全绕开平台走本地拾音（`genie/listen.py`）。
- 证据：2026-09-27 读文档 + 09-29 空白技能 120266 钉死 + 09-29 A/B 同框（「讲讲嫦娥」通、掉一个字就出局）。

**A7｜多一个「个」字就 0 POST：泛化的边界比想象中窄得多**
- 现象：`讲故事` 通，`讲个故事` 零 POST；`有什么好看的` 零 POST；`报菜名` 被听成「报蔡铭」就废。
- 误判：把这种当 bug 找，翻语料、翻实体、翻训练，一直不肯信是 ASR/边界的天然代价。
- 真因：整句匹配 + ASR 同音字天生低命中（桃/獭/累这类）。
- 结论：**把候选写短比堆整句划算**（短候选被听歪的概率低得多）；同音字的锅不要在代码里追；命中率表按「成/废」逐句存档，别凭印象。
- 证据：2026-09-29 真机泛化矩阵（✅/❌ 那张）。

**A8｜`ASK_INF` 的第二轮根本不回后端：那段是平台内置百科答的**
- 现象：我们返回 `resultType:ASK_INF` 想追问，音箱问了，用户答了，后端却一片安静；偶尔又冒出一句完全不是我们逻辑的漂亮回答。
- 误判：以为参数没配对（`selectParaInfo`/`askedInfos`）、以为会话没续上。
- 真因：**精灵在追问期间完全不请求后端**，那句话被平台自己的百科/闲聊接走了。`skillEndNluSession` 默认是 `false`（上下文默认保留），`sessionAttrs` 不对 webhook 开放 —— 这两条都不是给我用的旋钮。
- 结论：想要第二轮，就走 `SELECT`（回候选 + `selectIndexList`）；`ASK_INF` 当纯文案用，别指望数据回流。`RETURN_NLU` 更狠：0 POST，裸词还要空放 14 秒 —— 已判死。
- 证据：2026-09-29 空白技能 120266 实测；`genie/genielib/aligenie.py` 顶部 docstring。

**A9｜平台会复读上一轮的槽值，裸喊调用词就按旧问题又答一遍**
- 现象：只喊了一句调用词，音箱把上一轮那个问题的答案又念了一遍。
- 误判：以为是自己代码把空句子派成了问题。
- 真因：会话里槽位会被保留并复读下发（`slotEntities[].liveTime` 每轮 +1，**复读帧没有 `score`**）。
- 结论：`from_slots()` 里只认「这句话本身」，复读帧靠 `liveTime`/无 score 识别；`genielib/plan.py` 的注释就写着这条。
- 证据：2026-09-30 抓 4040 检视页原始报文对出来的（检视页只留 19 条、隧道重启会清 —— 要就趁早存）。

**A10｜第二轮的两副面孔：说「第二个」时槽位是空的，只能按下标**
- 现象：`SELECT` 出了候选，用户答第二轮，报文里的 `slotEntities` 值是个**空串**，按槽位取的逻辑直接漏。
- 误判：以为平台没回槽位 = 没匹配上，一度判「序号点菜走不通」（那一段窗口确实 0 POST）。
- 真因：第二轮有两种形态 —— ① 说序号：走 `selectIndexList:[n]`，**0-based**（故意喊「第十二个」回 `[11]`），槽位为空；② 直接说候选名（甚至不带调用词）：走文本 + `score:1.0`。两副都要接。
- 结论：按下标取「**我自己发出去的第 n 条原文**」覆盖 utterance 和槽值，别去字符串比对平台回的文字 —— ASR 听歪的字（`北及星`）也可能对上候选，一律换回我发出去那句（`genied.py:141` `menu_pick`）。
- 证据：2026-09-30 08:0x 真机两跳跑完整；09-30 14:0x 假报文（`青花`+`[0]`→`青蛙`）验下标这条腿。

**A11｜`MENU_MAX = 10` 是我自己卡的，不是平台卡的**
- 现象：片单写 14 条，实际只发出去 10 条，以为平台截了。
- 误判：怀疑报文长度、怀疑 SELECT 上限。
- 真因：`genied.py:51` 我们代码里 `[:MENU_MAX]`。临时调成 20，平台照收、音箱 20 条全念完。
- 结论：条数不是平台问题；但**念 10 条约 13.5 秒、念 20 条 40 秒+**，而第二轮开麦窗口只有约 9 秒（09-29 量的），堆条数等于让用户答不上。真上限**没测过**。
- 证据：2026-09-29 12:1x、09-30 08:0x；已收回 10。

**A12｜在线测试和真机是两层，谁都不能替谁判死**
- 现象：120248 在网页在线测试里怎么发都零 POST，我写了「这条链判死」；结果作者真机一喊，报文 `botId:10` 全打进来了。
- 误判：拿第 2 层（`/api/tools/test`）的结果当第 3 层（真机）的结论。
- 真因：网页测试绕不过官方技能抢答那一层，且它有自己的分隔符规矩（**自测只能用空格分隔，全角逗号 100% `UNKNOWN_DOMAIN`**；`/api/tools/test` 必须在 query 里带调用词，否则一律 `UNKNOWN_DOMAIN`）。
- 结论：判据强度 真机 > 网页 > `/test` > 本地函数，**只能往下用不能往上外推**；写下「判死」之前先问自己是在哪一层测的。
- 证据：2026-09-30 07:2x 当面更正；`docs/04-测试链路.md` 也留了这条不一致。

**A13｜训练没有任何可观测口径，别把 sleep 当流程**
- 现象：改完语料不知道什么时候生效，`trainStatus` 永远是 `NEW`。
- 误判：把「等 5~40 分钟训练」当成事实写进记忆、照着 sleep，A1 那轮零 POST 就是这么被带偏的。
- 真因：`POST /api/corpus/skills/<sid>/update/model` 无进度无提示，概览页那句「模型训练状态」在界面上找不到，状态接口全 404 —— **根本没有可观测的训练队列**，那个「40 分钟」是从在线测试表现倒推出来的猜测。
- 结论：判生效只有一个动作 —— **改完立刻真机喊一轮，看 `/log` 有没有那一句的 POST**。不要给自己造一个「等 40 分钟坐着」的条件。
- 证据：2026-09-29 07:1x 定；09-30 由 A1 反证。

**A14｜`reply` 一定会被 TTS 念出来，Content-Type 写成 text 平台就反序列化失败**
- 现象：接口 200，音箱要么念一堆标点/代码，要么什么都不念。
- 误判：以为有「只回数据不出声」的字段，以为可以给 HTML。
- 真因：`returnValue.reply` **必被念**，没有静默选项；响应必须是 JSON 且 Content-Type 不能是 `text`；带 `gwCommands` 时 `reply` 会失效。
- 结论：想少出声就改文案（短、口语、无 Markdown/HTML/URL）；协议细节看 `genie/genielib/aligenie.py`（47 行，注释里都在）。
- 证据：2026-09-27 读文档，09-28 真机第一次哑。

**A15｜一台音箱同一时刻只在一个技能的测试态里**
- 现象：两个技能并行开发，其中一个突然完全没流量，另一个好好的。
- 误判：以为隧道/域名漂了。
- 真因：真机测试绑定是排他的，「添加设备」+「打开技能测试」+ 6 位语音验证码这套流程会把上一家的绑定顶掉。
- 结论：多技能并行时，**每次开测先确认方糖当前在谁家**；验证码 180 秒过期，弹窗开着别导航走。
- 证据：2026-09-29 09:1x 踩过一次；08:43 全自动绑定跑通（`say -v Tingting` + whisper 取码 + 原生 setter）。

**A16｜分页参数读错一个字段，我以为 10000 条实体被抹了**
- 现象：拉实体列表回来只有几十条，以为平台删了我的数据。
- 误判：直接怀疑 PUT 覆盖了实体，准备回滚。
- 真因：列表接口的分页参数是 `pageNum`，而 entries 里回来的是 `pageIndex` —— 我把响应字段当请求字段传，读到空页。
- 结论：控制台接口每个字段都「请求/响应不对称」，**写脚本前先 GET 一次打印原始 JSON**；每次 PUT 意图还会重排所有 `userSay` 的 id，别拿 id 当主键存。
- 证据：2026-09-30。同族：实体值必须传**单个对象**（不是数组），`scope`/`resolution` 必须是字符串。

## B｜公网入口与隧道（cpolar free）

**B1｜零 POST 的头号真因：cpolar free 套餐重启就换域名**
- 现象：某一刻起平台再也不拨，`/log` 干干净净；服务、代码、隧道进程全都活着。
- 误判：连续怀疑大模型、怀疑代码、怀疑训练 —— 这一条我犯了不止一次。
- 真因：free 套餐的随机域名（`<CPOLAR_域名>` 这种形状）**每轮重启/重连必换**，而控制台里存的还是上一个域名。
- 结论：**每次重启 `cpolar-genie42` 之后**：① 从 `/var/log/cpolar/genie.log` 现抓 `Tunnel established at` 那行拿新域名；② 意图级 PUT 回写 `webhook.url`（不用点 UI）；③ 在盒子上 `curl -m8 https://<新域名>/health` 验。仓库里 `systemd/` 那几个单元之所以只写 `genied42` 随便重启，就是这个原因。
- 证据：2026-09-29 夜 ~ 09-30；`docs/04` 开头的安全提醒也是这条。

**B2｜「隧道活着」不能只看 127.0.0.1 的端口开没开**
- 现象：`127.0.0.1:4040` 打得开、检视页有内容，我据此写了「隧道正常」，结果平台照样进不来。
- 误判：把本地监听当成隧道可用。
- 真因：**那个监听口是 ssh/agent 自己开的，跟上游隧道通不通没有任何关系**。隧道断的时候本地面板照样起。
- 结论：判活必须顺着链路打到后端问一句 —— 在盒子上 `curl -m8 https://<域名>/health`，看 **200 / 25 字节**（自己那份）还是 **404 / 2578 字节**（旧域名，落到 cpolar 自己的页）。同理数 `StartProxy`/`pxy:pxy`/`prv:prv` 的条数来区分「平台没理我们」和「我们超时」。
- 证据：2026-09-30 定；`memory/cpolar-edge-reachable-by-aligenie-runtime.md`。

**B3｜真机零 POST 连续六轮全是假阴性：设备根本没醒**
- 现象：喊了六轮，`/log` 一条 POST 没有，我写了「平台不拨隧道」，准备回滚隧道配置。
- 误判：把「没 POST」直接读成「链路坏」。
- 真因：设备要么没被唤醒应答、要么房间里有人在说话/外放着直播 —— 那六轮里**一句都没进麦克风**。22:49 才发现设备应答是有的，只是我读的是上一轮日志。
- 结论：判据顺序钉死 —— **耳朵先确认设备开没开口**（`天猫精灵` 有没有应答）→ 再看 `/log` 有没有 POST → 才去查 cpolar 的 `pxy/prv`。房间有声音就别测；测就等空档（`curl -s -m3 localhost:8092/log | head -3`，最近 3 分钟没有真流量再喊）。
- 证据：2026-09-29 夜 → 22:49 破。同一条报文里「2 成 2 废」的对照表也是这轮存的。

**B4｜不 restart 也会换域名，而且域名会漂到另一个 edge**
- 现象：隧道进程 PID 没变、没人重启过服务，域名却换了；另一种是同域名不变但外面进不来。
- 误判：以为「没重启 = 域名安全」，据此写过校验脚本。
- 真因：① cpolar 重连（网络抖、edge 换）就重新分配随机域名；② 老 session 会死绑某个 edge IP，盒子到它 `Server failed to read StartProxy ... i/o timeout`，**这时候域名没变但公网是断的** —— 从别的机器 `nc -z` 那个 IP 却是 OPEN，是路由坏了不是 cpolar 全站挂。
- 结论：别把「域名」当常量存。**每轮从日志现抓 + `/health` 现验**；`i/o timeout` 那种状态只有重启隧道能治（并且接受换域名 + 回写控制台）。
- 证据：2026-09-30 01:03 补的第一条；第二条是 2026-10-04 21:25 在另一台设备上按同样流程复现的（那次新域名换到了不同 region 的 edge）。

**B5｜free 域名会被回收给陌生租户：你会打到别人家服务**
- 现象：`curl https://<CPOLAR_域名>/health` 回来一个完全没见过的 Flask 页面。
- 误判：以为隧道配错、以为后端挂了。
- 真因：随机域名是回收复用的，过期域名从此归别人。
- 结论：**每轮先 `curl 域名/status` 认是不是自己那份**（自己那份的 `/status` 形状是固定的）；文档/代码里绝不硬编码真实域名 —— 这也是本仓库全文用 `<CPOLAR_域名>` 的原因，写死了只会害下一个人去打别人的服务。
- 证据：2026-09-30。

**B6｜`.vip.cpolar.cn` 能过平台校验，但运行时永远不拨**
- 现象：控制台保存服务配置时校验通过（域名可达），我高高兴兴配完，结果零 POST。
- 误判：以为是 A1 或 A3，甚至以为平台在审核期不给流量。
- 真因：那一类边缘节点能通过「取认证文件」的校验，但阿里的拨测走不到；换 `-region=cn_top` 出来的 `*.r6.cpolar.top` 才真的被拨。
- 结论：**cpolar 起隧道就固定加 `-region=cn_top`**；「能过校验」不等于「平台能进来」，只有真机 POST 算数。
- 证据：2026-09-29 换 region 前后各一轮。

**B7｜`-subdomain` 回 4003：free 给不了固定域名**
- 现象：想省掉「每次回写 URL」这一步，加 `-subdomain` 起，报 `4003`。
- 误判：以为是拼写/权限/限流，重试了几次。
- 真因：free 套餐没有固定二级子域名，这条要付费最低档才能绑。
- 结论：要么接受「换域名 → PUT 意图回写」（我有脚本，4 分钟生效，不用训练）；要么换付费/自建入口。**付费档能不能稳定绑定我没测过**（没买）。
- 证据：2026-09-30。

**B8｜`pkill -f "cpolar http"` 会把自己的 ssh 一起打死**
- 现象：命令发下去，连接秒断，回来只能重连。
- 误判：以为盒子挂了。
- 真因：`-f` 匹配整条 cmdline，而我那条 `ssh ... 'pkill -f "cpolar http"'` 本身含这串字。
- 结论：模式写 `[c]polar:http` 这种自我免疫的写法；另外 `cpolar http` **默认后台化**（别指望命令前台返回），默认 yml 里预置了 `ssh:22` 和 `website:8080` 两条隧道 —— **别 enable 那两条**，会把不相干的东西挂上公网。
- 证据：2026-09-29 掉线过一次；坑 2/坑 3/坑 4 都在 `memory/cpolar-armbian-tunnel.md`（free 还限 1 进程 / 4 隧道 / 每分钟 40 连接）。

**B9｜`sort -u` 整份日志会把旧域名当成新域名**
- 现象：拿历史日志抓「当前域名」，结果 PUT 上去一个已经失效的域名。
- 误判：以为 cpolar 只写一次隧道行。
- 真因：一份日志里堆着几十轮 `Tunnel established at`，去重之后你根本分不清时间序。
- 结论：`grep 'Tunnel established' /var/log/cpolar/genie.log | tail -1`；别 `sort -u`。检视页 `127.0.0.1:4040/http/in` 只有根路径有 HTML（`/api`、`/status` 都 404），报文只留 19 条且是 base64，隧道重启会清 —— 原始报文要立刻存盘。
- 证据：2026-09-30；4040 取报文那段记在 `memory/genie-webhook-request-shape.md`。

**B10｜Mac 上打内网不加 `--noproxy '*'`，你会拿到一个假 502**
- 现象：`curl http://192.168.5.42:8092/health` 回 502，盒子日志里却一条请求都没有。
- 误判：判定「后端挂了」，差点去 restart 服务。
- 真因：这台 Mac 系统代理是 `127.0.0.1:7890`（Clash/mihomo），`scutil --proxy` 可查；**代理会把内网 IP 也吞进去**，502 是代理给的，不是服务给的。
- 结论：命令行加 `--noproxy '*'` 或 `-s --proxypm ""`；代码里见 C1（`curl` 和 `urllib` 对系统代理的态度不一样，所以手测通 ≠ 程序通）。
- 证据：2026-10-07（另一条链上撞的，同一条规则通用）。

**B11｜别把 7799 / 9090 挂到公网**
- 现象：想「外部也能触发电视」，把这些口一起塞进隧道。
- 误判：以为 `?key=` 是鉴权。
- 真因：`?key=` 不是 token（那次 401 是我测错了）；`/v1/ops/*` 这类运维口没有鉴权，`doubao-server` 只绑 `127.0.0.1:9090` 是故意的。
- 结论：公网只暴露 `genied` 那一个口；运维页只在局域网/回环。这条是我给自己的规矩，也建议守住。
- 证据：2026-09-30（`memory/genie-doubao-alert-0930.md`、`aligenie-doubao-chain-works-0930.md`）。

## C｜后端代码与协议（`genie/genied.py` + `genielib/`）

**C1｜`urllib` 必须显式禁代理，不然 `127.0.0.1` 也会被丢给代理**
- 现象：程序里打局域网/回环一律 502 或超时；`curl` 手测同一条 URL 是通的。
- 误判：以为对端服务挂了、以为 `reach()` 有 bug。
- 真因：macOS 下 Python `urllib` 会读系统代理（挂了 Clash 时被 `127.0.0.1:7890` 截走），`curl` 不读 —— 于是「手测通、程序不通」这种最气人的组合。
- 结论：建 opener 就写死 `ProxyHandler({})`，一次到位。仓库里 `genielib/targets.py:37`（全局 `_opener`）、`:137`（解短链那条）都是这么干的，注释就写着「局域网的机器绝不能走系统代理」。命令行同理见 B10。
- 证据：2026-09-29；`docs/_原始开发流水账.md` 第 143 行那条。

**C2｜慢活绝不能放进同步那一跳（平台只等 1.5~2 秒）**
- 现象：库里没答案时音箱整段沉默，或者答非所问；日志里那一跳 5 秒才回。
- 误判：以为平台超时是网络抖、以为多试一次就好，一开始还把「垫词 + 晚点到另一个喇叭」当成退而求其次的方案。
- 真因：注入延迟二分出来 —— **1.5 秒还播得出来，2.0 秒就不播了**（`genied.py:28-29`），而大模型要 5~20 秒。
- 结论：这一跳里只做「查缓存 + 秒回」，慢活起后台线程；`FAST_BUDGET=1.5`，超了就在日志打警告（`genied.py:327-328`）。注意**测这条要先躲开答案库缓存**（命中缓存 0.0x 秒，测不出大模型路径，见 D8）。
- 证据：2026-09-29 注入延迟实验（作者自己设计的，我原来写「3 秒肯定播不出来」被这个实验驳回）。

**C3｜派活前先探一次对端，别闷头撞 3 秒**
- 现象：电视那侧没起服务时，每条请求都要 3 秒才失败，整跳超出 C2 的预算。
- 误判：以为是网络慢。
- 真因：`requests`/`urlopen` 默认 connect 超时很长；探活没做。
- 结论：`reach()`/`alive()`（`targets.py:71`、`:96`）先 0.8 秒探一次，探不到直接走兜底文案；**探不到就说探不到，别调 `/frame` 装作放了** —— 手机/电视只吃现成地址，没片源就是没放成，谎报一次就要花一轮真机去圆。
- 证据：2026-09-29；`targets.py` 里 `play_video` 的注释。

**C4｜答案库的 key 是「原句去掉标点空格」，按裸话题名去查会得到假的「0 条落库」**
- 现象：灌完库写脚本核对，`if 话题 in d` 一律 0 条，我判定「/teach 全失败」，准备重灌。
- 误判：以为 `/teach` 没落盘、以为限流把整批吞了。
- 真因：`remember()` 存的是 `_norm(question)`（去标点、去空格），裸话题名根本不在 key 空间里。
- 结论：核对就按 `_norm(整句)` 去查，或者直接用服务自己的口径 —— **判生效只看 `/log` 里自己那句的时间戳行**；别用「我造的计数」当判据。
- 证据：2026-09-30。

**C5｜进程内缓存 `_kb` 是整档写回：手改 JSON 不重启，下一条回答把你删的脏条目又写回来**
- 现象：手工从 `answers.json` 删了十几条烂答案，确认文件里没了；一会儿再查，**它们又活了**。
- 误判：以为编辑没保存、以为有别的进程在恢复备份。
- 真因：早期 `_kb` 只在第一次读时加载，`remember()` 把内存里整档写回文件 —— 文件被外部改过的事实服务完全看不见。
- 结论：现在按 **mtime 重读**（`targets.py:342-360`，注释写着「批量预热是另起的脚本往 answers.json 里补货的，只缓存第一次读的话，灌完不重启服务就一条也认不出来」）。留两条给下一个人：① 临时文件必须和 `answers.json` **同目录**，`os.replace` 跨设备是 `EXDEV`（这条我在项目里记下了，**在这份快照上没复现**，别自己挪到 `/tmp`）；② 写盘包在 `except OSError: return ""` 里，**写失败是静默的**，见 C9。
- 证据：2026-09-30；`targets.py:499-503`。

**C6｜`/teach` 的后台线程会被隔壁会话的 restart 杀掉：发完必须回库核对**
- 现象：`POST /teach` 回 200、日志也打了「已开始」，结果 20 条只落进 12 条。
- 误判：以为豆包限流丢了一半、以为参数写错。
- 真因：`teach()` 是 daemon 线程（`genied.py:217`），而 `systemd/genied@box.service` 是 `Restart=always` —— 并行会话（或我自己）一次 `systemctl restart genied42` 就把没跑完的那批整个带走，**进程死了但请求早就返回 200 了**。
- 结论：批量任务发完 → 等 → **回库数一遍**（按 C4 的口径）→ 缺的清单落一个文件（我用的 `/tmp/kx_teach_pending.json`）→ 再补发。别把 200 当完成。
- 证据：2026-09-30；流水账里 `genied42 在 16:58:44Z 被重启` 那次就是隔壁会话动的。

**C7｜`/teach` 不能用 stdin 喂；0B 的 body 看着像成功，还会真的去起电视**
- 现象：脚本里用 heredoc / `--data @-` 走 `box-run.sh` 发 POST，远端回 200，一看日志——body 是 0 字节，什么都没发生。
- 误判：以为服务吞了请求、以为 `/teach` 坏了。
- 真因：expect 起的 ssh 没有可用的 stdin 转发，`curl --data @-` 读到 0 字节就发出去了；而 `/test` 拿到空 body 会走**默认那句**（`给我看一下初一的数学视频`）→ 电视当场播片。
- 结论：① 远程 POST 一律 `--data '<内联>'` 或 `--data-urlencode`，**绝不用 stdin**；② 判据里加一条「echo 请求长度」；③ 万一误触发，救火是 `7799/stop` + `pgrep -a mpv` 看有没有残留进程。
- 证据：2026-09-30 / 10-01；`memory/genie-teach-scaling.md`。

**C8｜`/test` 和平台真链路是两条腿，别拿一条的结果判另一条**
- 现象：`/test` 一切正常，真机却派错活（或反过来）。
- 误判：把 `/test` 的 `menu(10)(SELECT)` 当成「真机能路由」的证据，白跑一整天（09-29）。
- 真因：`/test` 走 `from_utterance`，平台流量走 `from_slots`，**中间多一道 `_search`**；而且 `/test` 的报文是我们自己造的（`"sessionId":"t-1"`、不带 botId），照样会真去起电视。
- 结论：① `/test` 只用来验「后端活着 + 文案长什么样」；② 看返回值看 `returnValue.reply`，`returnValue.output.spoken` 是空的**别当判据**；③ 拿 `/test` 做真机替身之前，先在 `GENIE_LLM_OFF=1` 的闸下跑。
- 证据：2026-09-30 下午；`genied.py` 里 `/test` 的默认句和 `reply(...)` 都在。

**C9｜手动起脚本不带 `GENIE_DATA` / `GENIE_OFFLINE_DIR`，所有写盘都是静默失败**
- 现象：明明「教」进去了，`offline_answer()` 恒为空，第二次问同一句还是不认。
- 误判：以为答案库读不到、以为 key 不对（其实是 C4 的另一半）。
- 真因：`remember()` 第一件事是 `if not OFFLINE_DIR or not answer: return ""`，环境变量没带 = 直接返回空串；写盘又在 `except OSError` 里，**一声不吭**。
- 结论：手动跑就照 `systemd/genied@box.service` 那 6 行 `Environment=` 原样抄（`GENIE_DATA=/var/lib/genie42`、`GENIE_OFFLINE_DIR=/var/lib/genie42/offline`、`GENIE_VERIFY=/etc/genie/aligenie`、`GENIE_PORT=8092`）；或者比对 `systemctl show -p Environment` 的输出。单元文件是**唯一的环境变量权威源**，别凭记忆。
- 证据：2026-09-30；`memory/genie-continue-last-answer-0930.md`。

**C10｜把「天气/星期/几点」存进答案库，等于埋一条过期答案**
- 现象：「今天星期几」第一天答对，第二天开始胡说；库里躺着 `今天星期三`、`明天（9月30日）中雨`。
- 误判：以为是 TTS 念错、以为是答案库串了行。
- 真因：答案库是**存死的**，日历类存一次错一年，天气新闻存一次错一天。
- 结论：① 当场算：`_clock_answer()`（只认带「今天/今晚/此刻/现在/今日」的句子，出现「明天/下周/明年」就交回原路 —— 否则「重阳节是几月几号」「电影几点开始」会被抢答成今天）；② 不入库：`remember()` 里 `_STALE_Q`/`_clock_answer` 一律 `return ""`；③ 盒子只有 UTC，家里说北京时间，代码里自己 `+8`（`targets.py:446`）。
- 证据：2026-10-01 第 8 站，`genie/kxpatch3.py:92-143` 里带完整注释。

**C11｜规则必须带量词：裸 `startswith(("出","考"))` 会把《出山》和考拉废掉**
- 现象：加了「出题别去放片」这条规则之后，《出山》这首歌点播不了、「考拉的视频」被当提问。
- 误判：以为是实体没灌、以为是 ASR。
- 真因：动词壳一剥就露出「出…题」的字头，裸前缀匹配没法区分「出几道题」和「出山」。
- 结论：规则写 `re.match(r"^出.{0,8}?[道题份套]", body)` 这种**带宾语的**；改完跑两套数 —— 526 句翻腿用例 + 2386 句回归用例（那轮回归 0 误伤才算过）。`genie/kxpatch3.py:26-35` 的注释就是这条。
- 证据：2026-09-30 下午。

**C12｜平台会把槽位念短，也会把单字槽乱匹配**
- 现象：说「怎么做手工贺卡」，回传槽位是「怎么做手工」，答案答成了别的东西；说「停车在哪里」把电视停了。
- 误判：以为实体值写错、以为 ASR 丢字（一半是，一半是实体只对上前半句）。
- 真因：实体只对上前半句时槽位被截短；单字触发词（「停」）做子串匹配会吃到长句。
- 结论：① ask 腿改用**原话**（`sent in full` 就用 `_strip_skill(utt)` 的整句，`kxpatch3.py:37-48`）；② 单字只认整句精确对上（`plan.py` 的注释）；③ 「有哪些/有什么」这类裸疑问词不进触发词表（`genied.py` `MENU_TRIGGER`）；④ 触发词要先剥调用词和句尾「吗呢啊吧」再整句一比一 —— 否则「名侦探柯南的人物有哪些」被抢成报菜名。
- 证据：2026-09-30 ~ 10-01，最后一次改动 md5 `0587836c`。

**C13｜`/log` 是新的在上，而且只在「没匹配上」时才记 —— `tail -n +N` 圈不出新一轮**
- 现象：想只看这一轮的新日志，`tail -n +N` 拿到的是旧内容；或者明明收到 POST，日志里搜不到。
- 误判：以为服务没处理、以为日志坏了。
- 真因：`/log` 倒序输出；另外 `genied` 对命中缓存的秒答路径**记得很粗**，要专门看新那几行。时间戳还是 UTC，和家里墙上的钟差 8 小时。
- 结论：判据按「**这一句、这一时刻的处理行**」去匹配（`[ask-cache] 「我刚才那句」...`），不能只数新增条数；比时刻先 +8。
- 证据：2026-09-29 / 09-30 两轮。

**C14｜`MENU_FILE_BY_INTENT.get(iid, "")` 那个默认空串，会把隔壁会话的菜单打成空**
- 现象：某一轮报菜名突然一条候选都不念，片单文件明明还在。
- 误判：以为读文件失败、以为权限。
- 真因：按意图 id 取片单时用了 `get(..., "")` 兜底，取到空串 → 路径退化成**目录**，读出来 0 行。
- 结论：① 表里没有就直接走全局那条，别用空串当默认；② `MENU_INTENTS` 这种「只放行这几个意图」的白名单，加意图时必须同步更新（120248 那条链挂死就是白名单没加对）；③ 多会话并行时**每个技能有自己的片单**（`片单.txt` / `片单-花生.txt`）。
- 证据：2026-09-30；`genied.py:51-107`。

**C15｜兜底必须写死，一句异常都不能让音箱听到 500**
- 现象：偶发情况下音箱不回话（平台的默认失败文案），后端却什么都没答。

- 证据：2026-09-28 起，代码里一直在。

## D｜大模型那条腿：限流、会话、答案的味道

**D1｜限流码 `710022004` 不是「登录掉了」**
- 现象：`llm-bridge` 上游 502，日志里 `DoubaoRateLimitError: Rate limited (710022004)`。我写了「豆包掉登录，要重新登录」。
- 误判：判成登录失效 → 差点去动账号（那会牵扯到设备上的凭据文件，成本很大）。
- 真因：就是**打太快/太多**，登录态好好的（后台一查还剩 23.6 天额度有效期）。
- 结论：① 见到限流/`verify` 字样**立刻停手，绝不自动重试**（MiGPT 侧的 `askWithRetry` 里加 THROTTLE 正则直接 `return`）；② `/teach` 循环里 `time.sleep(0.5)` 一条一条来（`genied.py:228`）；③ 对外文案区分两态：`llm_blocked()` 命中 `710022` 说「豆包被限流了」、命中 `verify_pending` 说「豆包要人工验证」（`targets.py:260` 附近）；限流多半几十分钟自己过去（这个数是观察值，**没测过严格分布**）。
- 证据：2026-09-30 10:1x 那一早，20 条灌库全没存进去，库停在 320 条。

**D2｜批量预热必须 `use_hist=False`：不然 N 个问题会串成一场对话**
- 现象：第一版灌出来的 65 条，62 条是废的 —— 答案开头是「…？。继续第十」。
- 误判：以为模型抽风、以为 prompt 没写好。
- 真因：`llm_say()` 默认 `use_hist=True` 会带上历史，批量灌 = 把上一问的追问串进下一答。
- 结论：① 批量一律 `targets.llm(q, use_hist=False)`（`genied.py:225`、`targets.py:183`）；② 灌完必须校验：`re.search(r"继续第|[？?]", 答案)` 命中就判废重灌。
- 证据：2026-09-30 炒菜类→运动类换词那轮。

**D3｜`verify_pending` 跨重启粘住：一条过期题面能让音箱整晚改口**
- 现象：明明验证早过了，`/health`/运维页一直红字「豆包要人工验证」，音箱跟着说这句话，真机测试全被带偏，我以为后端坏了。
- 误判：以为状态是实时的。
- 真因：`verify_pending.json` **开机读回来就一直挂着**，只有 `POST /v1/ops/verify/result {"status":"success"}` 会清；那张 11:13 的过期题面没人清，`llm_blocked()` 就对外一直说这句话。
- 结论：① 见到红字先「留档再清」（我留到 `/var/tmp/verify_pending.过期留档-0930.json`）；② `verify` 标志必须跨重启存活**但要能人工落一个成功**；③ 判「解没解」的唯一标准是真调一次看回不回话（见 D4）。
- 证据：2026-09-30 11:13 起粘；10-01 又踩一次（`docs/04`/流水账第 484 行）。

**D4｜状态缓存「拿不到当正常」，判活不能靠状态口**
- 现象：`llm_state()` 一切绿灯，实际每条都答不上。
- 误判：以为「状态好 = 能用」。
- 真因：状态口探测只给 0.6 秒超时、结果缓存 10 秒，**探测失败被当成正常返回**。
- 结论：判「大模型能不能用」只认一个动作 —— 真发一句（`targets.llm("讲讲塞翁失马，20字")`，0.1 秒回空串 = 不通）。`verify_pending.json` 时间戳没被重写**不代表解了**，别再拿它当判据。
- 证据：2026-09-30 流水账第 312 行；04:44Z 那次留档就是这种「看着像解了」。

**D5｜答案的味道只能用代码治：`_plain()` 那一长串残留**
- 现象：音箱念出来的答案一堆毛病 —— 念 emoji、两行粘成一句（「减二百五十二」）、把「斜杠/摄氏度符号/百分号」照字面念、`99%` 念反。
- 误判：以为要在 prompt 里教模型（那就变成往账号里塞指令，见 D7）。
- 真因：模型给的是**给人看的排版**，不是给 TTS 念的。
- 结论：全部在 `_plain()` 里治（`targets.py:370-435`，那一段注释写得很全）：剔 emoji、行间补「。」、剔网址、光秃秃冒号删掉、叠标点压平、`℃`→摄氏度、`–~`→到、`(\d+)%`→百分之N、`×÷`→乘/除、书名号/括号不成对就整段回退。**故意不动的也有**：`+` 和数字中间的 `-`（「常规+加时」「4-1击败」该念「加」「比」，代码分不出来 —— 这种只能回库里重问）。
- 证据：2026-10-01 第 7、8 站（`genie/kxpatch3.py:58-90` 带原文注释）。

**D6｜80 字硬上限把故事砍成没结局**
- 现象：故事类答案念到一半就「。」收尾，孩子问「后来呢」。
- 误判：以为模型就给了这么多。
- 真因：`_plain()` 为了「一次能念完」砍到 80 字，只退回句边界，不保证语义完整。
- 结论：**故事/长解释类别塞进秒答腿**；要么库里存短版本，要么走慢路径到电视。砍的位置遇到书名号/括号不成对要整段回退（D5 覆盖了语法，没覆盖语义 —— 语义这条我**没做**，算欠账）。
- 证据：2026-09-30 下午。

**D7｜`/teach` 会把抖音链接当答案存进库（念一长串 URL）**
- 现象：某几条答案音箱念出 `https://v.douyin.com/xxxx/`。
- 误判：以为答案库被污染是灌库脚本的锅。
- 真因：模型在答案里附带了链接，`remember()` 原样存；同时日志打的是**清洗前**的那串，看着像没存脏东西。
- 结论：① 入库前剔网址，**剔完为空就不入库**；② 日志要打印**真正会念出来的那一句**（清洗后的），别打原文；③ 抖音短链要上屏得先 `_short_video_id()` 吃 302 的 Location 解出 19 位视频号（`7799/tv` 只认 `/share/video/<19位>`），它常给一条已失效的短链（302 回首页），所以换句话再要一次、最多两次（`targets.py:134-153`）。
- 证据：2026-09-30；`docs/_原始开发流水账.md` 第 95 行。

**D8｜测大模型路径要先躲开答案库缓存**
- 现象：想验「慢路径 + 垫词」，结果每次都是 0.0x 秒秒答，测了个寂寞。
- 误判：以为慢路径坏了。
- 真因：`ask` 腿先查 `offline_answer()`，命中的句子根本不会打到模型。

- 证据：2026-09-30；C9 那条环境变量。

**D9｜不要往自己登录的大模型账号里塞 persona/指令**
- 现象：很顺手地想「让它说话更像一个角色」，或者「再发一次请求让它原样念一遍」。

- 结论：① 默认不发任何 system 提示词；② `llm_say()` 不再另发一次请求让它原样念（`targets.py` 注释写得很明白）；③ 要治味道就回 C/D5 用代码治。**这条是硬约束，不是我推荐的偏好。**
- 证据：我自己的运维笔记里那条「不往自己登录态的大模型账号里塞 persona」（2026-09-27，笔记不随仓库发布）+ `xiaoai/config.js` 注释。

**D10｜手动指定 `LLM_URL=http://127.0.0.1:7790/v1` 会被自己的探活判死**
- 现象：手起一条链，每条都秒回「豆包没答上」。
- 误判：以为模型挂了（其实是 D4 那个状态口的另一种表现）。

- 证据：2026-09-30；`memory/aligenie-two-device-goal.md` 里记的还是旧行为，以代码为准。

## E｜设备与音箱（小爱 / 方糖 / 电视 / 麦克风）

**E1｜Mac 上 launchd 起的 node，被「本地网络」隐私权限拦死**
- 现象：同一个上下文里 `curl`、`nc`、`ssh` 打 `192.168.5.x` 全部正常，唯独 launchd 拉起来的那个 node 进程连谁都连不上，`EHOSTUNREACH`。
- 误判：以为是 launchd 环境变量、以为 PATH/接口选择、以为防火墙规则。
- 真因：macOS 的「本地网络」权限是**按进程/按发起方**弹的，后台 LaunchAgent 起的进程弹不了框，就被静默拒绝。
- 结论：要么在 GUI 会话里起一次让它弹框授权，要么 **`ssh -L` 打回环隧道**（回环不需要该权限），手机侧配合 `AllowTcpForwarding=yes`。别的第一反应（改 PATH、改 unit）都是浪费时间的。
- 证据：2026-09-29/30，`memory/mac-node-lan-blocked.md`。

**E2｜音箱抓的是 URL：`VOICE_BASE_URL` 写 127.0.0.1 会「一句话也不说」**
- 现象：小爱答完就沉默，电视也没声音，日志一片正常。
- 误判：以为 TTS 没生成、以为凭据过期。
- 真因：小米音箱是**自己去抓那条 URL 的字节**（它还发不了 header），`VOICE_BASE_URL` 写回环 = 让它抓自己。
- 结论：① `VOICE_BASE` 必须保持**局域网 IP**，而 `API_BASE`/`LOCAL` 那套可以（且应该）走回环 —— **两套变量别合并**（`xiaoai/config.js` 里 `VOICE_BASE = k('VOICE_BASE_URL') || k('LLM_BASE_URL')`）；② 它发不了 header，所以音频 URL 不能靠 header 鉴权；③ 绝不用主 key 拼进 URL：MiGPT 引擎会把播的 URL **原样打进日志**（2026-09-26 就这么漏过一次），`gst_play` 报错里也常带完整 URI（含 `?t=`），落日志前都得抹。
- 证据：2026-09-26 + 09-30（E1 是同一条链上的另一半）。

**E3｜两份 MiGPT 同时轮询同一台音箱 = 小爱「时好时坏」**
- 现象：小爱回答时有时无、延迟乱跳，像玄学。
- 误判：以为小米云抽风、以为网络抖。
- 真因：Mac 那份和盒子那份 `ask.mjs --serve` **在轮询同一台设备的同一份凭据**，互相把对话记录抢走/消费掉。
- 结论：① 每次排障先 `pgrep -fl "ask.mjs --serve"` + `systemctl is-active migpt`，**确认全局只有一份**；② 权威源在盒子 `/srv/migpt`，Mac 那份 `launchctl bootout` + `disable`；③ 手起的 `nohup` 会撞 `EADDRINUSE`，但报错在 stdout 上很容易看不见。
- 证据：2026-09-30，`memory/migpt-runbook.md`。

**E4｜「点播腿不通」是我判反的：拦路虎是 `reach()`，不是 `GENIE_TV_URL`**
- 现象：喊「放一段街舞」，电视什么也不放；`GENIE_TV_URL` 当时写的是 `http://127.0.0.1:7799/tv`。
- 误判：我写「回环地址不行，必须换成局域网 IP」，还据此改过配置。
- 真因：**`GENIE_TV_URL=http://127.0.0.1:7799/tv` 本来就是对的**（它走 `call()`，不经 `reach()`）；真正卡住的是另一条路径 `reach()` 不认回环（见 D10）。同一时间「每条秒回豆包没答上」，是手动起脚本时把探活判死了。
- 结论：写「X 不行」之前，先确认失败的是哪一跳、有没有第二条腿在同时间成功。**机制解释只能跟在亲眼看到的差异后面**（这条是我的硬规矩之一，被作者纠正当场记下）。
- 证据：2026-09-30，`memory/aligenie-doubao-chain-works-0930.md` 明确「纠正」。

**E5｜开机自启的 `karaoke.service` 占着 HDMI 的 DRM master**
- 现象：`gst_play` 一上来就 `Cannot set CRTC: Permission denied`，画面永远出不来。
- 误判：以为驱动坏了、以为 kmssink 参数写错。
- 真因：DRM master 只能有一个，开机那个卡拉 OK 服务先占了。
- 结论：出屏前先 `systemctl stop karaoke.service`，放完再还回去；**任何会动设备状态的动作由作者本人点**（我不替他 stop/start 实体服务）。
- 证据：2026-09-30，`xiaoai/config.js` 注释原文。

**E6｜RK322x 只吃 540 档**
- 现象：给硬解丢 1080p，「播得慢」得离谱 —— 实测整片 352 秒跑了 8 分钟没完。
- 误判：以为网络不够、以为 rkvdec 没生效。
- 真因：这颗盒子硬解的天花板就在 540。
- 结论：挑片直接挑 540 档；`core_dep` 这类判定还和片子年龄相关（`76xx` 才解得出）。**更高码率能不能靠软解救没测过**（没试）。
- 证据：2026-09-30；614 秒那条是实测播出来的，能当基准。

**E7｜mpv/gst 的真正失败原因只打在 stdout，`--really-quiet` 把它吞了**
- 现象：出声/出屏失败，日志里 stderr 一片干净，什么线索都没有。
- 误判：以为播放器没报错 = 成功，转头去查网络。
- 真因：`mpv` 的失败原因在 **stdout**，而 `--really-quiet` 把 stdout 也关了；`gst_play` 同理。
- 结论：排查期临时去掉 `--really-quiet`、两边都收（`mpv --audio-device=alsa/plughw:0,0` 那条同理）；出声那侧用 `SAY_LOCK` 串行（`targets.py:32`、`:594`），别并发挤同一个 ALSA 设备。
- 证据：2026-09-30，`memory/migpt-runbook.md` + `xiaoai/config.js` 注释。

**E8｜`subprocess.run(text=True)` 撞 whisper 的非 UTF-8 stderr，把转写线程整个打死**
- 现象：本地那条耳朵链**聋了一天半**才发现 —— WAV 文件照常落盘，就是不写转写日志。
- 误判：以为 whisper 模型坏、以为麦克风没权限。
- 真因：`text=True` 解码 stderr 时抛 `UnicodeDecodeError`，异常在 worker 线程里，**主循环完全没感觉**。
- 结论：① 别在可能吐非 UTF-8 的子进程上用裸 `text=True`（用 `errors="replace"` 或按字节取）；② worker 全程 try/except，坏一句不许带走整条线程；③ 「WAV 照落、日志不写」就是它的**症状指纹**，下次直接认。**本仓库这份 `genie/listen.py` 已经是修过的版本**（`subprocess.run(..., stdout=DEVNULL, stderr=DEVNULL)` + 注释点名这个坑）；如果你手上的 `listen.py` 还是 `capture_output=True, text=True`，那是 09-28 的旧快照，先比 md5（见 F2）。
- 补充：09-28 那份旧快照真正缺的是那块胶水 —— 认本地唤醒词（`LISTEN_WAKE`，默认「小松鼠」）→ 把后面整句 POST 给盒子 `/local`（`LISTEN_BOX`）→ 盒子在 json 的 `念` 字段里回该念的话 → Mac `say -v Tingting` 念出来。旧快照只做「转写 + 写 `~/.genie/听到.txt` + 起 :8091 给人 curl」，**看着像链路通了其实一句都不派活**。本仓库这份已经是带胶水的新版（`route()` / `_post()`，`listen.py:61-93`）。
- 证据：2026-09-29；`docs/_原始开发流水账.md` 第 143 行。

**E9｜8091 那个转写页滞后 40 秒以上，不能当「设备开口了没有」的门**
- 现象：脚本里轮询 `localhost:8091` 想确认「听到第二轮了吗」，一直空，最后才出现 —— 整段漏转写。
- 误判：以为设备没听到，白喊好几轮。
- 真因：whisper 在 Mac 上排队跑，转写**落盘有几十秒滞后**。
- 结论：耳朵只能做事后取证，**不能当实时门**；要判「设备开没开口」，用后端 `/log` 里那一行、或直接听。
- 证据：2026-09-29 夜，`memory/genie-select-menu-impl.md`。

**E10｜语音测试的三条时间规矩（喊法本身）**
- 现象：命中率忽高忽低，同一句 2 成 2 废。
- 误判：以为平台在随机抽。
- 真因：① 调用词必须**独占一轮**（连着喊就整句废）；② 上一条没念完就喊下一条会被吃掉尾巴（10 条菜名念 36 秒 / 3 条约 6 秒，第二轮窗口约 9 秒）；③ 脚本里固定 `sleep 5` 会把第二轮当菜名尾巴吞掉，要按「约 1.3 秒/条 + 2 秒余量」算；④ 开麦续着时电视正在播豆包答案，**会被音箱自己听见**（`genied.py:308` 那句 `again = bool(spoken)` 就是在防这个）。
- 结论：`say` 语速和命中率**不是单调关系**（别指望调快调慢变好）；房间有真人说话/外放就别测（B3）。**「合成音它不认」是错的**（09-29 用 `say` 连联成功十几轮）；反过来「真人小孩口音能不能命中实体整句」—— **没测过**，而那才是真实使用者。
- 证据：2026-09-29 ~ 09-30 多轮。

**E11｜小米凭据 `.mi.json` 落在 cwd：unit 必须写 `WorkingDirectory=`**
- 现象：服务起来能跑，重启一次就要重新登录；或者反过来「明明登录过」。
- 误判：以为 passToken 过期。
- 真因：小米登录用的是 passToken，凭据文件名固定 `.mi.json` 落在**进程当前目录**；systemd 默认 cwd 是 `/`，每次起的目录不一样就每次「没登录」。
- 结论：`WorkingDirectory=/root/fly` 这类必须显式写（`systemd/doubao-server.service`、`llm-bridge.service` 都写了）；**顺带一句**：盒上那份 `.mi.json` 权限是 0644、`start-tunnel.sh` 是 0755 且内含 token —— 别 commit，文档一律占位（见 F10）。
- 证据：2026-09-30，`memory/migpt-runbook.md`。

**E12｜小爱的音量/暂停这两个旋钮，默认值都是骗人的**
- 现象：想压低音量压不住；喊「暂停」电视画面还在动。
- 误判：以为命令没送到。
- 真因：① `COIN` 那个字段压不住小爱；`MiNA.setVolume` 被 clamp 在 6..100，静音要走 **ubus 直发 0** 绕开它；② `SCREEN_STOP` 只能停小爱自己的播放，**掐不到 HDMI 上屏的画面**（那是盒子 gst/mpv 的进程，不归它管）。
- 结论：静音窗口 + 绕过 setVolume；停画面必须回头打 `7799/stop`（见 C7 的救火动作）。
- 证据：2026-09-26 ~ 09-30，`xiaoai/config.js` 注释原文。

**E13｜连说两句时新起的 gst 会撞上一条的收尾，整段动作要串成一条队**
- 现象：连着让音箱说两句，第二句必然没声音或爆音。
- 误判：以为 ALSA 被占是偶发。
- 真因：新的 `gst_play` 起来时上一条还在 `set_state(NULL)` 收尾，ALSA 设备还没释放。
- 结论：把「生成 → 落临时 mp3 → 播 → 收尾」整个串成一条队列（`targets.py:291` 的 `speak_on_screen` + `SAY_LOCK`（`:32`、`:594`））；`NATIVE` 词表原样交回小爱别自己接。
- 证据：2026-09-26 16:0x 起，`xiaoai/config.js` 注释原文。

**E14｜绝不重启实体设备（以及改设备状态的动作归作者点）**
- 现象：我执行过一次 `adb reboot loader`，命令**立刻返回 0**，我以为没事；约 4 分钟后设备真掉了，作者丢了 5 小时的电视输出。
- 误判：把「命令返回 0」当成「操作无害/已完成」。
- 真因：这类命令是异步生效的，返回值不代表结果；而设备是**实体资产**，重启窗口里他什么都测不了。
- 结论：① 任何重启/刷机/断电类动作**先要他本人点头**，我不动；② 破坏性操作要先说清「能不能回滚、代价多少时间」；③ 顺带一条相关的：别往他的大模型账号塞 persona（D9）。
- 证据：2026-10-05，我自己的运维笔记里那条「无人值守时绝不重启设备」（笔记不随仓库发布）。

**E15｜裸 URL 不带 `https://` 会被 `/v1/play` 的白名单门回 400**
- 现象：音箱说完「这就放给你」，电视什么都不播。
- 误判：以为片源坏了、以为 DRM（其实是 E5 那类，但不是一条）。
- 真因：模型给的是**裸串** `v.douyin.com/xxxx`，白名单校验要 scheme。
- 结论：入库/下发前统一补 `https://` 再交给 `/v1/play`；「只有走卡片的那几次能放出来」是同一族症状（卡片里带完整 URL）。另外 `.test()` 用在一个**带 `/g` 的正则上是有状态的**（`lastIndex` 会串味），逐条判定时要么去掉 `g`、要么每次 `new RegExp`。
- 证据：2026-09-26 ~ 09-30，`xiaoai/config.js` 注释原文两处。

## F｜多会话并行的坑（同一个目录两个人改）

**F1｜`box-run.sh` 远端 stdout 走固定 `/tmp/qoder-out.txt`：并行会话会盖掉你的输出**
- 现象：我发一条命令，拿回来的输出**整条是别人的**（或者把我上一条的输出当结果读），据此写了三个结论，全是假的。
- 误判：以为远端执行成功、以为输出对应我刚发的那条。
- 真因：`scripts/box-run.sh.example` 里 `expect ... scp "$BOX:/tmp/qoder-out.txt"` —— 路径是硬编码的共享文件，两个会话同时跑就是互相覆盖。
- 结论：① 每次自己重定向到带 pid 的文件：`... > /tmp/我的命令_$$.log 2>&1` 再 `box-run.sh get`；② **一次输出只能证明一件事**：判生效只认 `/log` 里「自己那句、自己那一刻」的行；③ 中文输出直接走 ssh tty 会被过滤掉，所以才有 base64+落盘那一圈；`bash -lc {…}` 那种写法会被 zsh 的花括号扩展咬一口。
- 证据：2026-10-01，`memory/box-run-output-race.md`（这条最贵，因为它让我在**其他坑**上得出过错误结论）。

**F2｜判新旧只能用 md5，git 判不了**
- 现象：想「把盒子上的代码拉回本地」或「确认线上是哪一版」，`git log` / `git diff` 给的答案全是错的。
- 误判：以为 git 能告诉我谁更新。
- 真因：盒上那份 git 基线只有一个 commit `73c1c4f`，而实际有 4 个文件是 `M`（都是这两个会话直接 scp 上去的，从没 commit）—— 历史里根本没有线上现状。
- 结论：**只比 md5**。逐文件 `md5sum` 对本地，我每轮都把这个数抄进流水账（例如 10-01 那次线上基准变成 `genied.py 5cfd750f / targets.py 34c915c3`，简报里给的 `73a19cdc` 和上两轮的 `efac2918` 当场作废，**别回推**）。共享状态没有 commit 习惯的话，md5 是唯一的真相。
- 证据：2026-09-30 ~ 10-01 反复三次踩。

**F3｜权威源是分裂的：同一个文件在三处，其中一处还是孤儿副本**
- 现象：改了 A 处、推了 B 处，线上跑的是 C 处。
- 误判：以为仓库就是权威源。
- 真因：① `genie/` 的代码在「本地 Mac 副本 / 盒子 `/opt/genie42` / 历史 `代码/genie/plan/`」三处都存在，其中 `代码/genie/plan/` 是**逐字节的孤儿副本**（谁都不推它）；② MiGPT 那份 `ask.mjs`（`016cf2e0`）和 `config.js`（`5742bb37`）来自**不同目录**；③ `scripts/deploy.sh` 打的是另一块板子（`142`、`/opt/genie`，那个路径根本不存在）；④ `genie/listen.py` 在 Mac 上那份**比源头新**，从源头推会把修好的覆盖回坏的。
- 结论：动手前先问「**这个文件线上现在跑的是哪一份**」，用 md5 认（F2）；`deploy.sh` 当反面教材读，别执行；孤儿副本直接当不存在。
- 证据：2026-09-30 ~ 10-01，`memory/project-code-map.md`。

**F4｜两个人往同一个 py 里贴补丁，用幂等锚点表才不会互相丢改动**
- 现象：隔壁会话把基线推回来的时候，会把我那三处下午的修复一起抹掉，而且**没有冲突提示**（整文件覆盖）。
- 误判：以为 scp 是「传文件」，只要文件名不撞就安全。
- 真因：整文件覆盖 + 并行 = 后来者赢，前者的修复静默消失。
- 结论：把修复写成**锚点表**再打：`genie/kxpatch3.py`（dry-run 只看锚点对不对，`--write` 才落盘；锚点对不上只打印、绝不覆盖别人的改动；已生效就跳过）。这个习惯还顺手治了「同一处改两遍」的重复注入。
- 证据：2026-10-01；`genie/kxpatch3.py` 文件头注释原文。

**F5｜`genied42` 随便重启，`cpolar-genie42` 不能重启**
- 现象：顺手 `systemctl restart` 了隧道服务，然后整链哑两小时（B1）。
- 误判：以为「服务都能 restart，都叫 restart」。
- 真因：重启 `genied42` 只丢内存里没跑完的线程（C6，代价可控）；重启 `cpolar-genie42` **换域名**（B1），代价要回控制台补。
- 结论：**推代码到盒子**那段规矩钉死：restart `genied42` 前先想 C6（有没有批量在跑），restart 完核对 `if took > FAST_BUDGET` 那种日志行还在；`cpolar-genie42` 只在「公网确实进不来」时动，动完立刻走 B1 的三步。另外 `systemd/genied@box.service` 是 `Restart=always / RestartSec=2` —— 崩了会自己起来，但也意味着**任何 OOM/异常退出都会顺手杀掉你的批量线程**。
- 证据：2026-09-30；`docs/_原始开发流水账.md`「推代码到盒子」段。

**F6｜批量预热期间别做语音/网页测试；跑完要收尾**
- 现象：灌库那几分钟，语音测试命中率莫名其妙崩了；回放跑完，「继续回答」把昨天的答案又播了一遍。
- 误判：以为平台抽风（其实是音箱听到了电视/风扇一样的人声，以及状态文件没清）。
- 真因：① 批量在跑时豆包额度在被打（D1）、`_HIST` 会话状态在动（D2）；② 上一条状态文件 `上一条.txt` / `上一条念过.txt` 是**持久化**的（`genied.py:57,89,100`），不清就是给下一个测试埋雷。
- 结论：**跑批 → 停手 → 清状态文件 → 再测**；批量预热和语音测试绝不并行。`GENIE_LLM_OFF=1` 那个闸在回放期挂着，期望日志出现「豆包已阻断，没打外网」。
- 证据：2026-09-30；`docs/04-测试链路.md` 第 8 条清单。

**F7｜`/tmp` 是共享的：上一轮的脚本和残留会把这一轮带跑**
- 现象：`/tmp/sel3.sh` 的 `tail -4` 里混进上一轮的「要哪个?」，被当成本轮的第二跳；`/tmp/sel11.sh` 第二跳写的是隔壁的调用词「豆包同学」，怎么喊都不成。
- 误判：以为 SELECT 逻辑坏、以为意图挂了（其实是脚本参数错）。
- 真因：`/tmp/sel*.sh`、`/tmp/sel1.json` 这类临时文件在同目录里被多个会话覆写。
- 结论：① 临时文件带自己的前缀（我一直用 `kx_`）；② 复用别人的脚本前先 `cat` 一遍看调用词；③ 判据只看后端 `/log` 那一行（F1）。
- 证据：2026-09-30 13:1x ~ 16:0x 两轮。

**F8｜换调用词是一件「要清全库」的事，不是一个常量**
- 现象：调用词从 A 改成 B 之后，老句子在答案库里教用户说 A，永远命中不了；泛化矩阵整片作废。
- 误判：以为改个配置就行（我一晚改了三版，每版都以为改完了）。
- 真因：调用词散在**四个地方**：平台 `invocationName`、`plan.SKILL_WORDS`、实体里灌的值、**答案库文案里那句「你说XXX」**。
- 结论：① 技能名和调用词分开挑（A5）；② 改完跑清单：`POST /api/skill?id=<技能id>` 读 `invocationName` 复核 → `SKILL_WORDS` 加新词 → 新词进实体 → 真机喊一句看 `ask-cache`；③ 库里所有提到旧词的句子跟着改；④ 表里的废词留着只是为了**把旧句子的壳剥干净**，不代表还能那么喊（`genielib/plan.py` 注释原文）。
- 证据：2026-09-30 ~ 10-01；`docs/04-测试链路.md` 第 16 条。

**F9｜快照 json / 子任务报的结论，一律要现拉一遍复核**
- 现象：`平台配置_*.json` 里 `webhook.url` 是好端端的旧域名，我照它写了「服务地址没问题」；另一轮子任务给的「线上 md5 是 73a19cdc」也是过期的，据此差点把新代码回推成旧的。
- 误判：把「导出过的那份」当「现在这份」。
- 真因：导出是历史，域名会漂（B1/B4）、线上会被隔壁会话推新（F2/F5）。
- 结论：域名从 `genie.log` 现抓（B9）、md5 从盒子 `md5sum` 现算、意图从 `GET /api/skills/.../intents/<iid>` 现读。`data/平台配置_*.json` **只能当历史读**，别拿它判现状。**子 agent / 别人的简报里的仓库结论，落盘前自己打开文件核一遍。**
- 证据：2026-09-30 ~ 10-01；我自己的笔记「子代理报来的仓库/运行结果要自己复核一遍」（2026-10-01，笔记不随仓库发布）。

**F10｜权限位偏松的那几个文件，一个都不能进 git**
- 现象：盒上 `.mi.json` 是 0644、`start-tunnel.sh` 是 0755 且**内含 authtoken**、`bridge.key` 在 `/root/.config/llm-bridge/`。顺手 `git add -A` 就把凭据摊开。
- 误判：以为「在我自己盒子上，权限无所谓」。
- 真因：这些文件是被脚本/服务写出来的，默认权限不受控；`box.pass` 我是专门放 `~/.config/llm-bridge/box.pass` 0600 的，别的没跟上。
- 结论：① `.gitignore` 里那些条目别删（本仓库全文用 `<占位>`）；② 密码只从 0600 文件读，不进命令行、不进日志（`scripts/box-run.sh.example` 注释原文）；③ 顺手 `chmod 600` 一下上面那两个 0644/0755 —— **这条我给了建议，落没落我没法在这份快照上确认**。
- 证据：2026-09-30 ~ 10-01，`memory/project-code-map.md` 的权限段。

**F11｜盒子时钟和日志时区是两件事，比时刻前先对齐**
- 现象：日志里「未来/过去」几小时的行为都有；判「这一轮的 POST」时圈错窗口。
- 误判：以为设备时钟没同步是唯一的坑。
- 真因：① `genied` 的日志打的是 **UTC**（跟家里墙上的钟差 8 小时，`targets.py:446` 那句 `gmtime(time.time() + 8*3600)` 就是为了绕它）；② 另外我记过一次「盒子时钟慢 16 小时」——那是那台板子的 RTC 没电/NTP 没起（**这一条在这份快照上没复现，只当历史读**）。
- 结论：所有「这一刻」的判据都写「**+8 再比**」；测批量脚本时宁可把时间窗放宽到 ±3 分钟，也别用整点对齐；`date` 先看一眼再动手。
- 证据：2026-09-30（UTC 那条在流水账里被反复提醒；16 小时那条在 `memory/genie-webhook-backend.md`）。

**F12｜同一个答案库被两边写：`remember()` 是整档覆盖，不是追加**
- 现象：一个会话在灌库、另一个会话在真人问答，前者的部分结果被后者的整档写回抹掉（C5 的多进程版本）。
- 误判：以为 `answers.json` 是 append-only。
- 真因：`remember()` 读内存档 → 加一条 → 写整档 → `os.replace`（`targets.py:496-502`）。**文件锁没有**。
- 结论：① 灌库期只做灌库（F6）；② 真要给答案库加并发写，得引入锁或改成一文件一条；**当前实现没做过并发保护，这一点我明确标注：多写入方同时跑的正确性没测过。**
- 证据：2026-09-30 ~ 10-01（答案库终值 476 条是这条链上「串行跑批」跑出来的）。
