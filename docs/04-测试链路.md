# 04 测试链路：怎么知道自己配对了没有

这条链最难的不是写代码，是**判据**。同一句话在四个地方测出来是四种结果，混用判据会让人连亏好几轮（作者自己写的原话：「差点被自己的过期导出带跑」）。这一篇把四层测试写成可复用的流程，每一层都标清：**跑在哪、怎么跑、看什么算过、看不见什么**。

素材只有三个来源：仓库里的 `genie/` 代码与数据、09-30 那份测试报告、作者的流水账与项目记忆。凡是这几处没写过的，本文一律写「没测过」。

**三条安全红线（复刻时照做）**
- 服务地址全文用占位 `<CPOLAR_域名>`；真实域名是 cpolar 免费套餐随机分配的，**重启 `cpolar-genie42` 就换域名，整条链哑掉**（09-30 记的）。密钥、token、设备 uuid、`userOpenId` 都不要进文档或仓库。
- 盒子内网地址全文写作 `<盒子IP>`，真实值不进这份文档。技能 id（`120248` / `120282` / `113665`）是仓库里已有的配置号，可以照着换成你自己的。
- 任何往真机/真电视发东西的动作（第 1 层的 `/test`、第 3 层的喊话）之前，先读第 5 节。

## 二、第 0 层：本地函数级

### 2.1 `handle()` 吃的是**内层 request dict**

`genie/genied.py` 的入口是 `handle(req, forced="")`，`req` 就是平台 POST 的**那个对象本身**（`sessionId` / `intentName` / `utterance` / `slotEntities` / `intentId` 这一层），不用再剥一层壳。`genielib/aligenie.py` 的 `parse()` 只做 `json.loads` + 是不是 dict，别的都不管。所以本地手测长这样：

```python
import genied
body, scheme = genied.handle(
    {"sessionId": "t-1", "intentName": "zhubajie", "utterance": "豆包同学，红烧肉怎么做",
     "slotEntities": [{"intentParameterName": "问题",
                       "originalValue": "红烧肉怎么做", "standardValue": "红烧肉怎么做"}]},
    forced="corpus")   # 不传 forced 时由 intentName 自己认路
print(body.decode())
```

`forced` 的规矩（读代码）：`intentName` 落在 `DEFAULT_INTENTS`（`""` / `default` / `默认意图` / `unknown` / `welcome` / `nlunlu` …）里 → 当方案B；否则当方案A。三个口 `/aligenie/corpus`、`/aligenie/nlu`、`/aligenie/webhook` 的区别只是把这个 `forced` 传成 `"corpus"` / `"nlu"` / `""`。`console/请求样例.方案A.json`、`请求样例.方案B.json` 就是这两种形状的**真实样本**（A：`intentName=看视频` + `grade`/`subject` 两个槽；B：`intentName=default`、`slotEntities: []`），样例里的 `requestData` / `requestId` / `skillSession` 后端根本不读。

### 2.2 两条腿分别对应什么测试

| 腿 | 入口 | 测的是 | 必测的形状 |
| --- | --- | --- | --- |
| `plan.from_slots(req)` | 方案A（平台已解析） | 槽位别名（`年级`→`grade`、`问题`→`query`）、`_search()` 决定要不要放片、槽位被平台念短时的原话救援、裸调用词带着旧槽回来要判成 `greet` | 猪八戒/豆包同学那条：`intentName=zhubajie` + `问题` 槽（09-30 报告第八节那 243 次全是这形状） |
| `plan.from_utterance(utt)` | 方案B（只有原话） | 词表判句：`STOP/NEXT/PREV/LOUD/SOFT` 控件词、`SCREEN_WORDS`/`LOOK` 点播词、`ASK_WORDS` 提问词、剥调用词 | 默认意图兜底那条；`/test` 和 `/local` 走的都是这条 |

这两条腿**对同一句会给出不同答案**，所以两条都要有测试。`from_slots` 里多一道 `_search(utt)`，`from_utterance` 里没有；09-30 下午作者拿 8277 句跑完 `/test` 才发现统计和平台对不上，就是这个原因（写进了记忆 `genie-copy-test-0930-afternoon`）。

### 2.3 `tests/simulate.py`：11 条用例 + 校验文件 + 状态口

```bash
python3 tests/simulate.py                                        # 起一个干跑实例全走一遍
BASE=http://<盒子IP>:8092 python3 tests/simulate.py              # 打线上那个
```

不带 `BASE` 时它自己拉起 `genied.py`，env 是 `GENIE_PORT=8099 GENIE_DRY=1 GENIE_LAN_CHECK=0 GENIE_VERIFY=tests/verify GENIE_DATA=/tmp/genie-test`。用例表覆盖：`/aligenie/corpus` 一条（s1 方案A）、`/aligenie/nlu` 五条（s2~s6）、`/aligenie/webhook` 五条（s7~s11，含「意图命中但问题槽取不到值」「裸喊调用词但旧槽被带回来」两种真机形状）。

**它怎么算过**（`main()` 里那段，照抄可用）：
- Content-Type 必须含 `application/json`（平台会反序列化失败，`aligenie.py` 顶上就写了这条）；
- `returnValue.reply` 非空 + `resultType ∈ {RESULT, ASK_INF}` + `executeCode == SUCCESS`；
- 行为类别靠 `reply` 文字反推：`reply == "您说。"` → greet；`"停" in reply` → stop；`"换" in reply` → next；ask 只认「回了话」（答案文本是模型给的，不能拿它断言）；其余算 play。

最后两跳是**协议级**的：`GET /aligenie/ab12cd34.txt` 必须回 200 + 纯文本原文（平台配 webhook 时要同步抓校验文件），`GET /status` 要能出 `player/screen/llm` 三段。09-29 那轮本地 11 条全过（记在 `genie-webhook-backend`）。

**两个必须知道的局限**
1. 这套用例里没设 `GENIE_OFFLINE_DIR`，而 `targets.offline_answer()` 第一行就是 `if not OFFLINE_DIR: return ""` —— 所以 ask 类用例只会回垫词（`我查一下啊。` / 被闸拦下的改口句），**这是在测协议，不是在测答案覆盖**。要测覆盖得自己带 env。
2. `GENIE_DRY=1` 只让 `targets.call()` 空转（不碰手机/电视），**挡不住豆包那一跳** —— `_chat()` 只看 `GENIE_LLM_OFF` 和 `reach(LLM_URL)`（默认 `http://127.0.0.1:7790/v1`）。结论：干跑请自己补 `GENIE_LLM_OFF=1`。**这条是读代码得出的，我没实际跑过 simulate.py 去验它到底会不会打出外网（没测过）。**

### 2.4 手动跑 `handle()` 的 env 坑（09-30 08:2x）

不带服务那份环境变量直接 `python3 -c 'import genied...'`，`DATA_DIR` 默认 `/var/lib/genie`、`OFFLINE_DIR` 默认空 → `remember_q()` 的写盘被 `except OSError` 静默吞掉、`offline_answer()` 永远空手回，**看着像功能坏了，其实是没 env**。必须：

```bash
GENIE_DATA=/var/lib/genie42 GENIE_OFFLINE_DIR=/var/lib/genie42/offline python3 ...
```

同一个坑在查答案库命中时也踩过一次（09-29 晚，`挑待灌`/核对脚本裸跑 `offline_answer()` 恒空，被误判成「一条都没灌上」）。

## 三、第 1 层：打盒子 `/test`

### 3.1 它是方案B 那条腿，不是真实体验

`do_POST` 里 `/test` 的实现只有四行：把 raw body 当句子，造 `{"utterance": …, "intentName": "", "slotEntities": []}`，然后 `handle(fake, "nlu")`。**`intentName` 写死空串、槽位写死空数组** —— 也就是说它评的是 `plan.from_utterance`，跟平台真发的 `intentName=zhubajie + 问题槽` 不是一回事。**要评文案/路由，得按 `from_slots` 的形状造 payload，或者直接用第 2 层。**（09-30 下午实测坐实，同一句在回放里是 ask、在平台上是 play。）

### 3.2 必须带 `--data`，否则电视会自己亮

```bash
curl -s --data "花生同学" http://127.0.0.1:8092/test        # ✅
curl -s -XPOST http://127.0.0.1:8092/test --data "句子"      # ✅
curl -s -XPOST http://127.0.0.1:8092/test "花生同学"          # ❌ 句子被当成第二个 URL
```

第三条写法 body 变 0B，落到代码里的默认语句 `给我看一下初一的数学视频` = 播放类 → **电视真的开始放视频**（09-29 00:10:12~00:10:30 连放三次）。补救：`curl 'http://127.0.0.1:7799/stop'`，再 `pgrep -a mpv` 空了才算停。

### 3.3 返回字段看哪个

看 `returnValue.reply`。**`returnValue.output.spoken` 是空的，别按它判命中**（09-29 实测）。批量回放时把这几列落成 TSV 最省事：`resultType`、`reply or comment`、`askedInfos` 有没有（= 开麦）、`intentName`。

一个有用的读法：`/test` 的 `resultType` 就能区分秒答与垫词 —— 命中答案库那条会回 `ASK_INF`（续麦），没命中走慢路径的回 `RESULT`。09-30 那份 8277 行 TSV 就是这么数出 **270 条 `ASK_INF` / 8007 条 `RESULT`** 的。

### 3.4 顺手把其它口读一遍（`genied.py` 的 `do_GET`/`do_POST`）

| 口 | 干什么 | 读它要知道的事 |
| --- | --- | --- |
| `GET /health`（或 `/aligenie/health`） | `{"ok":true,"pid":N}` | 唯一无副作用的存活探针；先打这个再打别的 |
| `GET /log` | 最近 80 行纯文本（`deque(maxlen=200)`） | **最新在最上**，配 `head` 用；`systemctl restart genied42` 会清空（09-29 实测被抹过一轮） |
| `GET /status` | `player/screen/llm` 三段 + `recent` 20 条派活记录 | 带 `GENIE_LAN_CHECK=0` 时三段是 `"没探"`，别当故障 |
| `GET /` | 网页版「听到的句子 → 干了什么」+ 豆包状态红字 | 5 秒自动刷新；`GENIE_LLM_OFF=1` 时单独标一行「测试期已阻断」 |
| `GET /aligenie/<文件名>.txt` | 平台校验文件 | 只从 `GENIE_VERIFY` 目录里给，越界 404 |
| `POST /teach` | 批量灌答案库、不出声 | 接受 JSON 数组 / 一行一条 / `{"问题":[…]}`；**每次截 60 条**；后台线程跑，只回 `{"在灌":N}` |
| `POST /local` | Mac 本地耳朵那条链的整句入口 | 走 `local()`，`greet` 直接不出声 |
| `POST /test` | 见上文 | 唯一会「自己造请求」的口 |

`/teach` 三个实测坑：① 不能用 stdin 喂（`box-run.sh` 是 expect 起的 ssh，`--data @-` 只发过去 0B，日志写着 `← POST /teach 0B` 却回 `{"在灌":0}`，看着像成功）——先 `put` 到远端 `/tmp` 再 `--data @/tmp/x.json`（09-29）；② 后台线程会被别人 `systemctl restart genied42` 杀掉，发完必须按 core 回库核对（09-29 发 20 只落 12）；③ 它抢豆包额度，**批量灌库和真机验证不要放在同一分钟**（09-29 19:2x 撞出两条「豆包没答」）。

### 3.5 `kxreplay.py`：把整份清单灌给 `/test`

`genie/kxreplay.py`（在 `~/Documents/天猫精灵语音遥控/代码/genie/`，仓库这份没带）就是第 1 层的批量化：

```bash
python3 /tmp/kxreplay.py /tmp/kx导入清单.txt /tmp/kxreplay.tsv     # 盒子上的用法
```

一行一句读清单 → 逐条 `POST 127.0.0.1:8092/test` → 落 5 列 TSV；每 500 条 flush 并打印进度。09-30 下午用它跑完 **8277 条、242 秒、一次豆包都没打**（前提：`GENIE_LLM_OFF=1` 闸挂着）。

**跑完必须收尾**：回放的最后一条会走慢路径污染 `上一条.txt` / `上一条念过.txt`，之后裸喊调用词不再回「您说。」而是重念旧答案。09-30 夜里就中过一次，清空这两个文件后 `--data 花生同学 /test` 才恢复回 `ASK_INF | 您说。`。

## 四、第 2 层：控制台网页在线测试

真接口是 `POST /api/tools/test`，body `{skillId, query, sessionId}`（页面「在线测试」每发一句就打它一条）。它是**唯一能同时验「平台 NLU 判成什么」和「后端收到什么」的低成本层**：09-30 11:2x 实测，`/api/tools/test` 真的会把请求打到盒子，`/log` 里出现的是 `botId:173019`（不是模拟流量的 `t-1`，也不是真机的 `botId:10`），说明它走的是完整 NLU。

四条实测规矩：

1. **query 必须带调用词前缀**（09-30 11:2x）。`为什么会有空间站` → `UNKNOWN_DOMAIN`；`豆包同学，为什么会有空间站` → `SUCCESS / intentName=doubao / 问题:为什么会有空间站`。
2. **全角逗号换空格**（09-30 下午）。`小狗汪汪，X` 100% `UNKNOWN_DOMAIN`，`小狗汪汪 X` 100% 通。但同一轮里 `豆包同学，X` 反倒全通 —— **分隔符按技能逐个实测，别外推**；真机 ASR 给的就是空格，所以线上没事，只是自测脚本要用空格。
3. **每句一个新随机 `sessionId`**（09-30），否则上一条的 `ASK_INF` 上下文会串进来。
4. **规模**：2 并发跑 100 句约 60~90 秒，比真机快一个数量级，可以当 100 句规模的回归用（09-30 记的）。

这层的两个「假阴性」要背下来，否则会把好链判成死链：

- 早期结论「在线测试对**未发布**技能一律 `意图/null`」是 09-28 09:5x / 09-29 反复复现过的（技能 `status:OFFLINE` 时连灌过值的句子也回 null）。09-30 11:2x 更正：**主因其实是缺调用词前缀**，不是网页接口不可信。
- 随机句子的 `UNKNOWN_DOMAIN`（包括「句子少打一个字就打不中」—— 09-30 05:1x 把实体原句「照样子说**带**全神贯注的例句」少打一个「带」立刻 `UNKNOWN_DOMAIN`）**只是这个接口的现象，不代表真机不通**。铁证：120248 在网页侧带任何前缀任何句子都是 `UNKNOWN_DOMAIN`、零 POST（09-30 11:2x），而真机 09-30 07:2x 证明它一直在通（`skillId:120248 / intentName:zhubajie` 连续 POST 进来）。作者那句「别再拿 120248 做批量测试，用 120282」就是这么来的。

`243 次平台真链路`那批原始数据（备份 `测试原始数据/kx_platform_all.tsv`）读法：列依次是 `句子 / executeCode / intentName / reply / 槽位`；按行首第 2 列 `awk -F'\t' '{print $2}' | sort | uniq -c` 数出来 **SUCCESS 226 / UNKNOWN_DOMAIN 16 / 平台内容安全 1**，加起来正好是报告正文那句「243 次调用」。两个读的时候必踩的坑：① 末行少一个换行，`wc -l` 给 242；② 有 7 行（`awk -F'\t' 'NF>5'` 能抓出来）缺了换行，**下一条记录的句子被粘在本行第 5 列的尾巴上**，整行变 9 列 —— 所以这份文件严格数出来是 250 条记录，**它和「243」差在哪我没逐条对上（没核过）**，引数的时候按上面那个「行首第 2 列」口径引，别自己按行数算。内容安全那条是平台自己挡的（`三角洲行动怎么压枪` → `HTTP200` + 「这个问题我无法与你继续探讨」），不是后端坏了。

## 五、第 3 层：真机语音（唯一算数的一层）

### 5.1 判据顺序，反过来用必错

09-29 那天前 5 轮真机全部「零 POST」，一度判成「平台不拨 webhook」，晚上 22:49 一句话就通了 —— **全是假阴性**。之后定死的顺序：

1. **先看设备有没有开口**（听，或看 Mac 耳朵 `curl http://127.0.0.1:8091/` 有没有转写出「你好主人 / 您说」）。一个字没出 = **唤醒失败**：房间有人在说话、电视外放盖住了、或调用词被听歪。跟平台无关，别去查隧道。
2. 设备念了追问（「您想问什么?」）**但盒子 `/log` 零 POST** → 这时才去查 cpolar 隧道日志：先 `wc -l < /var/log/cpolar/genie.log` 记行号 N，喊完 `tail -n +N`，grep `pxy:pxy.*New connection` / `prv:prv.*New connection to: 127.0.0.1:8092`。自己 `curl https://<CPOLAR_域名>/health` 会出这两行，可用来验格式。
3. 有 POST 进来，才去查意图 / 语料 / 实体 / 我们的代码。

配套三条硬规矩（都是实测）：
- **`/test` 回放会绕过 NLU，不算真机证据**（09-29：`/test` 出 `menu(10)(SELECT)`，真机那边一条 POST 都没有）。
- **`/log` 是最新在最上**，所以 `tail -n +$((N0+1))` 这种按行数圈新一轮的写法圈不出来，会把 8 分钟前的旧 POST 当结果；判 POST 只认报文时间戳，或按关键字 + 时间去重（09-29 batch C 就错在这，误报过「重播/停 POST 了」）。**POST 基线要在开口之前取。**
- **每喊一轮立刻读日志**，别攒到最后一次读（`/log` 会随别人 restart 被清空，09-29 22:06 那轮判据就这么没了）。

### 5.2 怎么「喊」

`say -v Tingting` 合成音是真能用的（09-29 05:41~06:1x 连联成功十几轮，报文带 `botId":10`）。时序要求：
- 唤醒词 → 调用词 → 句子，**相邻两句 `say` 之间别超过 1.5 秒**（09-29 结论：之前每轮 `sleep 5` 造成的「零请求」很可能是聆听窗口已关）；整句一次 `say` 完更稳。
- 第二轮的麦很贵：**从「要哪个?」落地到麦自己关只有 9 秒**（09-29 21:0x 逐段 wav 转写量出来的）。固定 sleep 全错过，短菜单（3 条 ≈ 6 秒念完）窗口才够用。
- 喊之前先转写最近几段 wav，确认房间里没有真人对话、电视没在放东西（09-29 19:19~19:21 耳朵转写出来的是父子读书打卡对话，那两轮白发）。
- **耳朵不能当路由判据**：ASR 会把答案里的名词听歪（09-30 上午「上海海港」→「上海海岛」、「山东泰山」→「山东派山」）。「没听到原话」≠「没路由」，判据看盒子 `/log`。
- 候选词要先能被听清：09-30 00:0x 用 `say` + whisper 自筛 20 条菜名，**只有 6 条能完整说中**（`四面楚歌 / 长颈鹿 / 青蛙 / 鹦鹉 / 脑筋急转弯 / 冷笑话`）；「企鹅→起鹅」「北极熊→被指雄」这类别再拿去测第二轮。

### 5.3 真机验过什么（可当基线）

- 平台等这一跳的预算：**1.5 秒播、2 秒不播**（09-29 注入延迟二分法量的），所以 `GENIE_BUDGET` 默认 1.5s、超了就在 `/log` 打警告行。

## 六、`/test` 自测前必须先确认这句不会被判播放（血泪）

判据**不是句子像不像提问**，是盒子日志里那一行：

- `ask-cache(音箱秒答)` / `ask-tv(电视说)` → 安全，是在问答。
- `放「…」→ 上电视=True` → **这句话把电视点着了**，你的自测顺手播了一条视频出来。

真实翻车例子（09-29 那轮，记录里的日志时间戳 `21:13:34`）：自测发了一句 `冷笑话`，被路由到播放腿 —— `放「笑话」→ 上电视=True`，电视真起了一条笑话视频，只能用 `--data 停` 收场。根因是 `plan.py` 的 `TOPICS["笑话"] = ["笑话","段子"]`：`from_utterance` 里 `p.topic` 一旦命中词表，`wants_video` 又为真（或压根不需要 `SCREEN_WORDS`），就直接判 `play`，库里那条 `冷笑话` 答案永远轮不上。改法二选一：去掉 `TOPICS["笑话"]`，或在 `handle` 前加一道「`offline_answer` 命中就归 ask」——**这两条当时都没上线，所以至今这条腿仍然会翻车**。

可用的自查手段（按侵入性从低到高）：
1. 带对 env 先跑一次 `targets.offline_answer(句子)`，命中 → 这句大概率能走 ask；**没命中就说明它会掉进慢路径或播放腿**，别在有人用设备的时候测。（09-29 实测：片单 10 条逐条过 `offline_answer()` 全 HIT，所以第二轮绝不会出现电视出声。）
2. `tests/probe_video.py` —— **只读探针**：只问豆包要链接、把卡片和 `find_share` 解出来的链接打印出来，不放电视、不出声。想验视频腿先跑它。
3. 拿 `片单生成.py` 那种「挑进来的一定能秒答」的思路，给自己造一批**保证落在 ask 腿**的测试句。

顺带一条同类劫持（值得抄进自己的检查表）：09-30 04:3x 抓到 `MENU_TRIGGER` 里塞了裸子串「有哪些」，于是 `名侦探柯南的人物有哪些` 被劫持成报动物菜名还顺手开麦；09-30 06:5x 复查仍在，直到 07:5x 才把裸疑问词删掉、并改成整句精确匹配。**任何「子串触发词」都会劫持正常提问。**

## 八、时区坑：盒子 `/log` 是 UTC，Mac 是 CST，差 8 小时

09-29 早上差点因为这件事误判：拿「09:14 我念的那一句」去 `/log` 里找，看到的最新一条是 `01:12:03`，看着像「POST 没进来」——其实 `01:12Z + 8 = 09:12 CST`，是同一条。**对时间一律先把盒子时间 +8。**（本文所有「09-30 08:0x（盒子 UTC 00:06~00:09）」这种双写法就是从这来的。）

## 九、全量回放怎么做（8277 句这一套）

### 9.1 8277 句从哪来

不是手写的，是笛卡尔积：09-29 下午重做了一份灌库材料（`素材/材料/`，源头 `词表.py` + `材料生成.py`），**1442 个实体词 × 96 个句式模板 → 8277 条整句**（`06_整句_全部.txt`），外加 1279 道题。这 8277 句后来整批灌进 120248 的「问题」实体 101852（`totalCount` 1670 → 9828），**送法**：本机起 `127.0.0.1:8099` 小 HTTP 服务，已登录页面里 `fetch` 一次拿走 196 KB，先 `crypto.subtle` 对 SHA-256，再开 5 路并发 —— **142 秒 8158 个 POST、0 失败**（09-29）。作者明确写了：随机串（gzip+base64 分块）不能靠抄，中文整句才抄得动。

`console/gen_questions.py` 是更早、更小的一份：跑一次打印条数并写 `/tmp/qvals.json`（09-29 那份是 **1435 条**），`console/gen_corpus.py` 则生成方案A 的语料 CSV。**回放用的清单就是 `kx导入清单.txt` 那份一行一句的纯文本。**

### 9.2 `挑待灌.py` 的用途

它把生产命中规则**照抄一遍**用来算「一条答案能顶几句」，从而按边际增益贪心挑本批 20 条，写 `/tmp/batch.json` 给 `/teach`。命中规则（和 `targets.offline_answer()` 一致，读代码核过）：存了 `k` 之后，`y` 能秒答当且仅当

```
norm(y) == norm(k)  或  core(y) == core(k)  或  (len(k) >= 5 且 k 与 y 互为子串)
```

`core()` = 先剥前缀动词壳（`能不能/给我/讲讲/介绍一下/…`）再剥后缀（`的故事/的来历/是谁/是什么/吗吧呀呢/…`）。跑之前要准备两个文件：`/tmp/ans42-dump.json`（盒上库拉下来的 `answers.json`，**文件名必须叫 answers.json**，塞进目录里改名会 `_load_kb()` 静默返回 0 条）和 `/tmp/qvals.json`（实体清单）。

### 9.3 「一条豆包答案只顶 2~3 句」的真实数学

09-29 07:0x 用生产 `offline_answer()` 真跑 1435 句量的（不是估的）：
- 灌库前只有 **56/1435** 能秒答；按 `_core()` 折完仍有 **1345 个不同 core** —— **「一条顶九种问法」这个假设基本不成立**。
- 真会并成一条的只有 `X是谁 / X的来历 / 讲讲X的故事 / 讲讲X的知识` 这一族（core 全折成 `X`）。**`怎么做X` 和 `X的做法` 折不出同一个 core**；动物族的 `X吃什么 / X住在哪里 / X能活多久 / X长什么样` 各是独立 core，一句只顶一句，这类占了大头。
- 贪心挑 20 条 → 顶掉 46 句（09-29 08:0x 第二轮：库 283→303，覆盖 93→**139/1435**，剩 1296 句 ≈ 65 批）；一批 20 条实跑 **3 分 10 秒 ~ 3 分 16 秒**，约 10 秒/条（含 0.5s 限流睡眠）。
- 结论账：全库要补齐 ≈ 17~18 小时连续豆包调用，只能拆夜里几批。所以「一条答案 = 2~3 句」不是修辞，是 `covers()` 算出来的。

### 9.4 命中率怎么统计（三种口径别混）

| 口径 | 数字 | 怎么来的 |
| --- | --- | --- |
| 全量回放秒答率 | **270 / 8277 = 3.3%**（09-30） | `kxreplay2.tsv` 的 `resultType` 列数 `ASK_INF` |
| 抽测秒答率 | **28 句问答里 1 句秒答 ≈ 3.6%**（09-30 06:1x 出首条秒答；之前几轮写「0 句秒答」是把口径说死了） | 网页轮 + 盒子 `/log` 里 `ask-cache` 计数 |
| 覆盖率**上界** | **答案库条数 / 10000** —— 382/10000 ≤ **3.8%**（09-30 04:0x，库从 376→380→382；后面 394/398/402 同理 ≈4%） | 分母是平台实体硬上限 10000（`totalCount:10000`），分子是当时 `answers.json` 条数 |

那个 `382/10000 ≈ 3.8%` 是**上界**，不是实测命中率：它说的是「就算抽到的句子全是库里的，也不可能超过这个数」。而 63%（09-30 上午 216 句那轮）之所以高，是因为那 216 句是**特意从库里挑的** —— 换成全量就掉到 3.3%，**不是退步**。作者反复强调的一点：**瓶颈从「路由」挪到了「答案覆盖」**，因为路由在实体灌完之后已经是 226/243 通。

统计前置条件：`GENIE_LLM_OFF=1` 全程挂着，凭据是 `llm-bridge` / `doubao-server` 两个服务 **70 分钟日志 `-- No entries --`**，加上 `/log` 里 22 行 `豆包已阻断，没打外网`。**先证明零外网，再谈数字。**
