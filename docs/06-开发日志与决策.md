## 2. 岔路口：每条我当时怎么选、为什么

### 2.1 「让音箱问大模型」——同步等 vs 先垫词后补播

- 备选 A：webhook 里同步调豆包，拿到答案直接 return。
- 备选 B：那一跳只回一句「我查一下啊。」，答案晚一点从**另一个喇叭**（电视）出来。

选了 B。决定性证据是 09-29 用注入延迟二分量出来的：**平台那一跳只等 1.5～2 秒**（1s 播、1.5s 播、2s 不播、3s 不播），而豆包实测 4.7～20 秒。A 在物理上不可能。

事后只动摇过一次，而且是被误读：`targets.py:24` 那个 `GENIE_LLM_TIMEOUT` 默认 **45 秒**，09-30 04:1x 有一轮「慢路径像是断了」，真因是这句在 45 秒上撞墙 + 隔壁并发在打同一个账号；同句重问一次，电视就出声了。**超时设置撞墙长得很像功能坏了** —— 但注意这 45 秒是**后台补播那一跳**的预算，不是同步那一跳；把两者搞混就是我那轮误判的来源。这条 1.5~2 秒的约束从头到尾没变过。

### 2.2 「要自由词」——继续攻 NLU vs 承认做不到

- 备选 A：继续找平台的口子（透传、结果透出、默认意图、`sys.other` 全匹配实体、所见即可说）。
- 备选 B：放弃平台，自己收音。

先花了一整天把 A 穷尽：09-29 08:44~08:47 在一个**什么都没配**的空白技能（120266 三只松鼠 / 意图 199508，0 语料 0 参数 没训练，只挂 webhook）上做对照 —— 裸调用词收得到，「调用词 + 任意一句话」的尾巴**在平台的 POST 里就没有了**，不是麦克风切的是 NLU 切的。四条否证做完，A 判死。

然后 B 落地成 `genie/listen.py`：Mac 常驻耳朵，能量断句 → whisper.cpp 转写 → POST 盒子 `/local`。唤醒词故意用一个不和平台撞的本地词，两条链各管各的。

**如果只抄一条经验：这条。** 我在此之前已经往「能不能不枚举」里投入了相当多轮次；真正的转折不是找到新接口，是**设计了一个能一次否决整类方案的实验**（空白技能 = 白名单为 0，任何"绕过白名单"的机制都应该在 0 白名单上也能 POST）。设计不出这种实验之前，试错是没有终点的。

### 2.3 「覆盖更多话」——扩句式泛化 vs 扩句子枚举

库里一条豆包答案只能顶 2~3 句（只有「是谁/来历/故事」那一族会折成同一个 core），所以每一句都要花钱问豆包。两条路：

- 泛化：把 `_LEAD`/`_TAIL` 加宽，让 `能不能放足球吗 / 我想看足球 / 讲讲足球` 折成同一个 core。09-29 早上宽了一圈，十种问法确实全折成一个（可 `targets.py ccba66c5`）。
- 枚举：往实体那 10000 格里灌整句。09-29 灌到 8158，09-30 顶到过 10000。

**两条都在用**，但比例是后期才看清的：泛化便宜（一条答案顶十句）但覆盖面永远补不完；枚举贵（一句一问）但**它是唯一能证明「这句路由得到」的东西**。09-30 下午那次 8277 句全量重测之所以有价值，就是因为它把「我以为泛化能兜住」的 526 句（6.4%）打回原形 —— 那些句子实际是「出题/讲故事」，被播放腿抢走了。

挑哪句先灌是可以算的：`genie/console/挑待灌.py` 照抄 `_LEAD/_TAIL/子串兜底` 做贪心，一条答案顶几句是算出来的，不是猜的。09-29 08:0x 那批实测：库 303 条、实体 1435 句里 139 句能秒答，剩 1296 句 ≈ 65 批。

### 2.4 「公网入口」——自建 vs cpolar，`.vip.cpolar.cn` vs `.r6.cpolar.top`

free 套餐 + 不想动路由器，于是用 cpolar。踩了两层：

1. `-subdomain` 固定域名被 free 套餐拒（4003），只能拿随机域名 → **每次隧道重启域名都变，控制台里那个后端 URL 必须跟着回写**。10-01 之前已经变过三次（`7b2b1eed`、`63e4dfcd` 都 404 过）。我的处理是把「回写服务地址」做成每轮保活的固定动作，而不是想办法让域名不变。
2. 后缀不是装饰：`.vip.cpolar.cn` 能过控制台的 URL 格式校验，但运行时**永远连不上**（09-29 那堵「平台不拨隧道」的墙，一部分就是它）。必须 `-region=cn_top` 拿 `.r6.cpolar.top`。

**教训形状**：平台的「校验通过」和「运行时能用」是两件事，凡是只在配置期校验的字段，都要当成未验证的。

### 2.5 「报菜名」——让平台存候选 vs 服务端每次现算

`SELECT` 是平台给的唯一一个「第一轮就把候选交给用户、第二轮免导入」的机制（09-29 09:0x 做进 `genied`）。当时的岔路是候选从哪来：

- 让平台/实体存着一份菜单 → 改一次要走控制台 + 训练，而且受实体上限。
- 服务端从**本地答案库现算**（`MENU_MAX=10`）→ 改库即改菜名，零控制台动作。

选了后者。附带收益：第二轮平台回 `selectIndexList:[下标]`（**0-based**），后端认下标而不是认词 —— 09-29 14:0x 特意改成这样，因为 `say` 合成音会把词听歪（花生同学→花生童学、企鹅→起鹅），认词根本救不回来。

代价也实测到了：菜单念完要花时间，**而第二轮那个窗口就是从这一点一秒里扣掉的**。三个实测数（别当成同一件事的三个版本）：

| 什么时候 | 菜单内容 | 念完 |
| --- | --- | --- |
| 09-29 10:1x | 10 条**整句**「讲讲一箭双雕…」 | 约 36 秒；插话太早（24 秒）被当成噪音，回「没听清…再说一次吗」 |
| 09-29 12:1x | 20 条**短词**（成语/动物） | 40 秒往上，连着四轮没人来得及答第二轮 → `MENU_MAX` 收回 10 |
| 09-29 22:0x | 10 条短词 | 约 13 秒；**但裸喊调用词也会触发一次菜单，于是连念两遍 = 26 秒**，我按上一轮反推的「触发后 6~18 秒开口」正好卡在第二遍中间、麦根本没开 |

能确定的是：**条数和菜名长短都在吃这个窗口，而双份菜单是最隐蔽的一项**。所以「菜单条数 ↔ 第二轮窗口」是这个功能唯一真正好用的旋钮，上线前自己念一遍掐表（我最后用的是 4 条，09-30 那份假报文 0.02s 回、窗口够用）。

还有两个当时的误判修正掉了：候选条数的上限**不是平台的** —— 09-29 12:1x 把 `MENU_MAX` 临时调到 20，真机上平台照收、20 条全念完，所以 10 这个数纯粹是我们自己画的（超过 20 仍未测）；以及「第 N 个」按序号选这件事，**我在 09-29 判过一次死**（见 §3.4），09-30 才又活过来。

### 2.6 「答案的味道」——往大模型账号里塞 persona vs 用代码治

有过一次很省事的诱惑：在豆包账号里写一段系统提示词，让它输出适合 TTS 的句子。我没有这么做，也建议你不做 —— 那是往**别人会封号的登录态账号**里注入指令，收益（省几行后处理）远小于风险。

替代是 `genielib/targets.py` 的 `_plain()`：把 `99%` 换成「百分之99」、`×÷` 换成「乘除」、`+` 和数字中间的 `-` **故意不碰**（改了会伤「1-2 比 3」这种比分写法）；以及 10-01 那两条：问「今天/现在」的日历钟点**当场算**（盒子只有 UTC，自己 +8），天气/新闻**不查库也不入库**（存一次就错一天）。库因此从 481 删到 476。

这是这 6 天里唯一一类「越改越不像 AI 而是像工程」的工作，但它是文案层全部收益的来源 —— 07 篇那些数字（190/216 条结尾没句号 = 「听着像半句话」的来源）没有一条是靠提示词解决的。

### 2.7 「控制台怎么操作」——点 UI vs 直接调接口

前期全靠点 UI，慢且不可复现。09-29 起改用登录态浏览器里的同源接口：`x-csrf-token=ctoken` 才能 POST/PUT；`/intents` 分页字段叫 `pageNum`、`/entries` 叫 `pageIndex`（响应是 `totalCount`/`result`），`entries` 只收单个对象。灌 8277 条这件事从「不可能手点」变成 142 秒。

**有一条我给自己定了死规矩，希望你 also 守住**：意图级 `PUT` 必须带 `defaultIntent:true` 并保留 `executeLogic`，否则**默认意图被抹掉、整链哑**。09-30 那次裸 `PUT`（没带这个字段）就是「120248 半夜全量 UNKNOWN_DOMAIN」的头号嫌疑，而当时我先把锅甩给了平台（见 §3）。另外：**永远不要点「提交审核 / 发布 / 解除绑定」**，那三类动作是不可逆地作用在真实账号上的。

## 3. 我判错的四次（最有用的部分）

### 3.1 「平台没拨隧道」——连续六轮假阴性

09-29 16:00~23:5x，真机六轮零 POST，我按顺序查了：隧道、域名、控制台后端 URL、训练状态。全都不是。

真相是**设备当时没醒**，而且更糟的是：其中两轮（23:33 / 23:47）同一个词成了、另两轮（23:48 / 23:52）废 —— 也就是说那段时间房间里有一场我没注意到的直播在抢答。我把「我的请求没到」和「设备根本没听见」混成了同一个结论。

修好的判据顺序（写进 04 篇）：

1. **先看设备有没有开口**（我自己那只 Mac 耳朵听得到）；
2. 再看盒子 `/log` 有没有 POST；
3. 最后才查隧道。

顺序反过来的时候，我会去修一个根本没坏的东西。另外 **`/test` 是回放、绕过 NLU，它成功不算真机成功的证据** —— 这句话我说过三次，因为我又犯了三次。

### 3.2 `710022004` 是「对话 id 指着一个已删除的豆包话题」，不是限流

09-30 10:0x 开始豆包回这个码，我按「限流」处理：不再戳、等它自己放行、并且把「撞限流就别多问」写进了运维口径。10-01 才发现：`llm-bridge` 存的 `conversation_id`（盒子 `/root/.config/llm-bridge/doubao_convs.json`，键是 **「客厅」不是 `default`**）指向一个我已经在豆包那边删掉的话题。

`curl -X POST 127.0.0.1:9090/v1/conversations/reset -d '{"user":"客厅"}'` 重建会话，同一把钥匙 **4.7 秒**出完整答案。

**这条我造成的实际损害**：中间有相当长时间我按「账号被限」压着不灌库、还撤过一次已经写对的代码。误判的根源是**把一个稳定的错误码解释成一个时变的现象**（错误码是「这个对象不存在」，我却读成「你现在问太多了」）。以后再撞固定错误码，先怀疑配置/引用，再怀疑速率。

### 3.3 「verify 状态」会骗人

`/v1/ops/state` 那个红字（要人工验证）以前是纯内存态，重启就丢；修成从 `verify_pending.json` 读回后，反过来变成**粘的**：只有 `POST /v1/ops/verify/result {"status":"success"}` 会清。09-30 11:13 那张过期题面不清掉，`targets.llm_blocked()` 就一直对外说「豆包要人工验证」→ 音箱当场改口，真机测试全被带偏。

清之前先留档（`/var/tmp/verify_pending.过期留档-0930.json`）再清。现在 `llm_blocked()` 回空串。

同族的坑还有：**判 idle 干不干净别用 `pgrep -f "pactl subscribe"`** —— 它会匹配到你自己那条 ssh 命令行，我拿它误报过一次「监听泄漏」。

### 3.4 「别指望序号」——我判死过一次，第二天它自己活了

09-29 12:0x 那轮我连着撞了三次「第二个」：12:06:16 菜单还没念完就说 → 没回应；12:09:07「花生同学 → 您想问什么 → 第二个」→ 音箱回 **「抱歉您尚未绑定天猫魔盒」**；上午 10:23 同样一句回的却是「闹钟还没有设定」。两种都是被**平台全局意图**抢走，一个字节都没到我后端。当天我在记录里写死了结论：**「点菜只能念菜名本身，别指望序号。」**

09-30 08:0x 全程真机又成了：「小狗同学，你能干什么」→ 0.02 秒回 SELECT → 我喊「第二个」→ 报文带 `selectIndexList:[1]` → 换回「青蛙」→ 音箱秒答。还量出两条新事实：**序号从 0 数起**（故意喊「第十二个」回 `[11]`），以及说「第 N 个」时**平台只给下标、槽位值是空串**，所以后端必须自己记住刚发出去的那份名单。

差别在哪我**没有确证**。最可疑的是「当时那台方糖处在另一个技能的测试态、以及我开口太早被当成菜名尾巴」——但这两条都只是解释得通，不是实验证明的。

**这条为什么值得单独列**：一个「实测判死」的结论，有效期可能只有一天，而且它的失效条件我们并不掌握。凡是靠**一次性不命中**得出的否证，写下来时务必带上「在哪台设备、什么会话态、开口时机」——我那三次失败恰恰三次都撞在念菜单中途。**否证要写清前提，否则下一个人（包括第二天的我）会拿它当定律。**

## 4. 这 6 天的两条元经验

1. **能一次否决一整类方案的实验，值一百次试错。** 空白技能（白名单 = 0）和注入延迟二分（1.5s/2s）各自把一整条研究线关掉了；而没有它们的时候，我在这两条线上各花了大半天。
2. **把「我不知道」写在文档里，比写得圆满更值钱。** 01 篇末尾两张清单（「没测过」+「我自己记录里互相打脸四处」）就是这么来的 —— 我自己的原始记录里至少有四处前后矛盾，我没能拆开验证，列出来而不是编一个能自圆其说的解释。

| 「第 N 个」被官方抢走的确切条件 | 没做对照 | 会 —— 直接决定菜单条数怎么设 |

| 候选超过 20 条 / 10000 上限的适用口径（每实体？每技能？） | 只在一处顶到过 | 按 1 万条做规划之前得自己验 |
| `actions` 播素材库音频 / `playTts` / `gwCommands` 覆盖 reply | 全没测 | 会 —— 这是「让音箱自己念长答案」唯一可能的正路 |
| 慢路径答案的味道（数字、比分、`+` 号歧义）| `待重灌.2026-10-01.txt` 82 条没重问 | 会，但很机械 |
| 批量回放收尾必须清 `上一条.txt` / `上一条念过.txt` | 已写进文档，没做成脚本 | 忘了就表现为「裸喊调用词重念旧答案」 |
| 认证文件校验在 120282 上到底怎么过的 | 无记录 | 见 01 篇 §附二.1 |
