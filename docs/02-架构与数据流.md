## 2. 端口与服务表

| 口 | 进程 | 监听在 | 谁能访问 | 鉴权 |
| --- | --- | --- | --- | --- |
| **8092** | `genied.py`（unit `genied42.service`） | `Server(("0.0.0.0", PORT))`，`PORT` 代码默认 **8090**，unit 里 `GENIE_PORT=8092` | 局域网任意机器 + 经 cpolar 进来的阿里云端 | **没有**。唯一的"共享秘密"是校验文件：`GET /aligenie/<md5(技能id)>.txt` 从 `GENIE_VERIFY` 目录里原样吐出去，文件名跟域名无关 |
| **7790** | `llm_bridge.py`（unit `llm-bridge.service`，`--host 0.0.0.0 --port 7790`） | 0.0.0.0 | 局域网；**公网不挂**（cpolar 只转发 8092） | `Authorization: Bearer <bridge.key>`。播放器加不了 header，于是有派生 token：`token = hmac(bridge.key, 整条资源路径+query)[:32]`，形态是 `/v1/audio/<id>/t/<tok>?url=…` 或 `?t=<tok>`。**只认那一条资源**，换个 id 就 401 |
| **9090** | `doubao_server.py`（unit `doubao-server.service`，`--host 127.0.0.1 --port 9090`） | 只有回环 | 只有盒子自己 | 无（鉴权在 7790 那层） |
| **7799** | `ask.mjs --serve`（MiGPT 触发器，unit `migpt.service`） | `.listen(7799, "127.0.0.1")`（`ask.mjs:217`） | 只有盒子自己 | 无 |
| cpolar | 盒子上的 cpolar 客户端 → `127.0.0.1:8092` | 出站到 cpolar 中继，路由器不用开端口 | `https://<CPOLAR_域名>.r6.cpolar.top/` | 无 |

三个「为什么」：

- **9090 为什么绝不能挂公网**：它持有你那个大模型账号的登录态（cookie/session），`/v1/ops` 还是给人手点验证码的页面，而且这一层根本不鉴权。挂上去 = 把账号交给公网。要看它，`ssh -L 9090:127.0.0.1:9090 root@192.168.5.42` 再开 `http://127.0.0.1:9090/v1/ops`（这句提示就写在 `genied.py` 首页里）。另外：**只绑回环也解释了「电视上为什么不弹验证页」** —— 它不弹，得你自己 ssh 进去点（2026-09-30 实测确认）。
- **7799 为什么只绑 127.0.0.1**：它的口能直接抢你家话筒和电视 —— `/play`、`/volume`、`/stop`、`/song`、`/tv`。`/play` 还多一道门：只肯播本机门（`VOICE_BASE`）前缀的链接，不做开放转发器（`ask.mjs:183`）。
- **主 key 为什么绝不进 URL**：MiGPT 引擎会把正在播的 URL 原样打进日志（2026-09-26 就这么漏过一次），所以 URL 上只挂那条派生 token，`config.js:163` 还把 `/t/<32hex>` 和 `url=` 从日志里抹掉。

**8092 是公网口，但它一条鉴权都没有。** `POST /`、`/test`、`/local`、`/teach` 谁都打得上来，`/test`、`/local`、`/teach` 还会真去打大模型、真起电视。复刻时至少在路由器/反代上给 8092 加个路径前缀或来源限制，别像我这样裸着挂 free 隧道。

`genied` 自己的口（`genied.py:370-482`）：

| 路径 | 干什么 | 备注 |
| --- | --- | --- |
| `POST /`、`POST /aligenie/{corpus,nlu,webhook}` | 接平台 | `corpus`/`nlu` 强制走对应解析，`/` 和 `webhook` 按 `intentName` 自己判 |
| `GET /aligenie/xxx.txt` | 平台校验文件 | 只允许 `GENIE_VERIFY` 目录内的文件，做了 realpath 前缀检查 |
| `GET /` `/status` `/log` `/health` | 本机看的页 / 依赖探活 / 最近 80 行日志 / `{ok,pid}` | 首页 5 秒自动刷新，并写明豆包还剩几天登录态 |
| `POST /teach` | 静默灌答案库（≤60 条/批，条间 sleep 0.5 s） | 不出声、不动电视 |
| `POST /local` | Mac 耳朵那条链的入口 | 没有平台替你念，所以"该念的话"放在 json 的 `念` 字段回给 Mac |
| `POST /test` | 手造一句原话走 `plan.from_utterance` | **它不带 `intentId` → SELECT 必判「menu没成」；它也不等于平台真链路** |

依赖方向（谁调谁）：`genied` → `7790`（`LLM_URL`，`Authorization: Bearer bridge.key`）、`genied` → `127.0.0.1:7799/tv`（`GENIE_TV_URL`）、`genied` → `127.0.0.1:9090/v1/ops/state`（`BRIDGE_STATE`，0.6 s 拿不到就当正常，不能拖累那一跳）；`ask.mjs` → `7790` → `9090`；`genied`/`ask.mjs` 都不反向调用对方。

一个必踩的坑：`targets.reach()` 只放行「和盒子同网段」的地址，`127.0.0.1/localhost/::1` 是 2026-09-30 才单独放行的（`targets.py:78`）。所以 `LLM_URL` 在 unit 里仍写 `http://192.168.5.42:7790/v1`；而代码默认值（`targets.py:22`）是 `http://127.0.0.1:7790/v1`。同一个坑的 Mac 版：`urllib` 会读系统代理，挂着 Clash 时局域网请求被 127.0.0.1:7890 截成 502 —— 代码里 `build_opener(ProxyHandler({}))`（`targets.py:37`）是唯一解。

## 4. `genied` 的三条腿（已逐行核过 `genied.py`）

`handle()` 是所有句子的漏斗，顺序是：`menu_pick` 换下标 → 判「继续回答」→ 判报菜名 → `plan` 判动作 → 秒答/垫词/派活。

**腿 1：命中答案库 → 音箱秒答（0.0x 秒）**

- `p.action == "ask"` → `targets.offline_answer(p.query)` 命中 → `aligenie.reply(答案, "ASK_INF")`，日志 `ask-cache(音箱秒答)`，`again=True`（续麦）。
- 秒答不碰任何外网，所以平台 1.5 s 预算绰绰有余：实测 0.00 s / 0.01 s / 0.03 s（2026-09-28、09-29、09-30 各轮）。
- 两句题外话：问「今天星期几/几号/几点」根本**不查库**，由 `_clock_answer()` 当场算（盒子只有 UTC，代码自己 +8）；问天气/新闻**也直接不查库**（§5 那道门）。

**腿 2：没命中 → 0.02 s 回垫词 → 后台打大模型 → 电视喇叭出声**

```
handle()  ask 且 offline_answer 空
  ├ remember_q(q)                 写 /var/lib/genie42/上一条.txt，并把 上一条念过.txt 清空
  ├ targets.llm_blocked()         问 9090 的 /v1/ops/state：要人工验证 → 「豆包要人工验证」
  │                               710022 → 「豆包被限流了」，都改口回「…，晚点再说给你。」
  ├ 立刻回 "我查一下啊。" RESULT  实测 0.02 s（2026-09-27 真机）
  └ threading: answer_slow(q)
        ├ targets.llm_say(q)      一次 _chat 同时拿文本 + audio:{format:"mp3"}
        │                         max_tokens=800、LLM_TIMEOUT=45 s
        ├ targets.remember(q,text) 回填答案库 → 同一句第二次问就是腿 1
        ├ targets.say_on_tv(mp3)  mpv --no-video --audio-device=alsa/plughw:0,0 --volume=85
        │                         SAY_LOCK 串行（两条话不能叠），subprocess timeout=120 s，放完文件留着
        └ 成功 → mark_sent(q)     写 上一条念过.txt：一句答案只播一次
```

实测的模型耗时：5.1~5.7 s/条（2026-09-28）、3.6 s（2026-09-29 23:0x）、4.7 s（2026-10-01 撤闸后）、「黄瓜怎么种」那条 **1 分 54 秒**（2026-09-30 07:2x，撞过 45 s 上限）。所以这一跳**永远不可能**同步等到答案 —— 这就是垫词存在的全部理由。

**腿 3：SELECT 报菜名 + 「继续回答」续播**

- 报菜名入口：`is_menu_ask()` 把调用词和句尾语气词剥掉之后**整句精确比对** `MENU_TRIGGER`（`你能干什么 / 报菜名 / 菜单 / 片单`… 10 条）。第一版是子串匹配，「名侦探柯南的人物有哪些」被劫持去报动物菜名 —— 那个 bug 在 2026-09-30 关掉了，**「有哪些」这类裸疑问词现在不是触发词**。
- `menu_reply()`：`intentId` 必须在 `MENU_INTENTS`（`199486`、`199538` → 槽名「问题」），候选读 `DATA_DIR/片单.txt`，199486 单独读 `片单-花生.txt`（`MENU_FILE_BY_INTENT`），取前 `MENU_MAX=10` 条；回 `resultType:"SELECT"` + `askedInfos:[{问题,intentId}]` + `selectParaInfo{candidateList, parameterReplyMatch:true, selectIndexMatch:true}`，并把这份候选按 `sessionId` 记进 `SENT_MENU`。实测 0.00~0.02 s 出得来（2026-09-30 08:0x 真机 0.02 s）。
- 第二轮：平台自己开麦、把说的话跟候选配对，回 `selectIndexList:[n]`。`menu_pick()` 用这个下标取回**我发出去的那条原文**，覆盖 `utterance` 和槽值 —— ASR 听歪（「北及星」「青花」）也救得回。下标 **0-based**：故意喊「第十二个」回 `[11]`（实测 2026-09-30 08:0x 真机）。说序号这种话时槽位是**空串**，只有下标，所以必须自己记那份名单。
- 时序预算（实测 2026-09-29~09-30）：候选 3 条 ≈ 6 s 念完、4 条 ≈ 7 s、8 条 ≈ 8.6 s、10 条 ≈ 13.5 s、20 条 40 s 往上；**从「要哪个？」落地到麦自己关只有 9 秒**。10 条是 `MENU_MAX` 卡的，不是平台卡的（写 14 行也只发 10 条）。候选必须读本地文件 —— 现搜豆包（5~20 s）当不了候选源。
- 「继续回答」族（`CONTINUE_TRIGGER` 8 个词，同样整句精确比对，且拦在报菜名前面）：`last_q()` 读 `上一条.txt` → `offline_answer()` 从库里捞 → 秒答（实测 0.02 s，2026-09-30）。三种结果：有答案 → `RESULT` 秒答 + `mark_sent`；`上一条念过.txt` 等于这一条 → 「这条刚才已经说过啦」；有 Q 无答案 → 「上一条还在查呢」；无 Q → 「没有要续的上一条问题」。两个文件都是落盘的，服务重启不丢。**跑批量回放之后必须清空这两个文件**（`8277` 全量回放的副作用，见 2026-10-01 流水账），否则裸喊调用词会重念旧答案而不是回「您说。」。

## 5. 答案库为什么能「自己长大」

机制就三句话：**答完就写回、按主题词认、写之前先洗成能念的话。**

1. **回填**：`answer_slow()` 里 `targets.remember(question, text)`（`genied.py:244`）。第一次问走电视那条慢路，答案同时写进 `answers.json`；同一句第二次问就是腿 1 的音箱秒答。`/teach` 是同一件事的静默版（只入库不出声）。
2. **key = `_norm()`**：去掉空白和 `，。？！?!,.`（`targets.py:311`）。库里存的 key 就是「讲讲嫦娥奔月的故事」这种**原句去标点**，不是裸话题名 —— 你要查某条灌没灌上，比 `_core(key)`，别 grep 裸词。
3. **三层匹配**（`offline_answer()`，`targets.py:458-478`，命中后**还要再过一遍 `_plain()`**）：
   - 精确：`kb.get(_norm(q))`；
   - 主题词：`_core_index().get(_core(q))` —— `_LEAD` 剥「讲讲/说说/介绍一下/能不能/我想/放/看」，`_TAIL` 剥「的故事/是什么/怎么来的/想看/吗/吧」。实跑验证：`讲讲嫦娥奔月的故事`、`嫦娥奔月是什么`、`介绍一下嫦娥奔月` 的 core 都是 `嫦娥奔月`（我今天用仓库这份代码跑的）。**一条答案顶十来句**，不然 357 个话题 × 35 种句式得灌一万多条；
   - 兜底：库里任意 key 长度 ≥5 且与原句互相包含。
4. **`_plain()` 把大模型的 markdown 收成能念的话**（`targets.py:370-430`）。以下三组是我把样例喂进仓库这份 `_plain()` **实跑出来的输出**（形状取自流水账记录过的真实回复，例如 2026-09-30 那条日志里的原始文本 `# 🥒黄瓜种植方法（科学作业可用）`）：

   | 喂进去 | 出来 | 干了什么 |
   | --- | --- | --- |
   | `# 🥒黄瓜种植方法（科学作业可用）` + 三条 `1. 2. 3.` + 一句带 `https://www.iesdouyin.com/share/video/…` | `选种与处理：选饱满无霉变的种子，温水泡4小时。土壤要求：疏松肥沃，pH值6到7。播种深度：埋进土里大约1厘米深，浇透水。想看过程可以打开照着做。` | 丢掉 `#`/`-`/`*`/`>` 开头的行、剥行首编号、**行与行之间补「。」**（不补会粘死、数字被念错）、**剔掉网址**（否则音箱念「https 点点」） |
   | `唐朝小故事（适合小朋友）` + 两条 `- ` 列表 + `✅ 代表作《静夜思》…` + `要不要我再给你讲一个，你来让我原样复述？` | `代表作《静夜思》《望庐山瀑布》。` | 删 emoji、短标题行整行丢、**丢掉把话头甩回来的反问尾巴**（否则音箱像在等人接话） |
   | `全场命中率99%，三分线外×2分，温度区间18-25℃，比分4-1领先，常规+加时3:3。` | `全场命中率百分之99，三分线外乘2分，温度区间18-25摄氏度，比分4-1领先，常规+加时3:3。` | `%` 整个挪到数字前才念得对、`×`→乘、`℃`→摄氏度；数字中间的 `-` 和 `+` **故意不动**（`4-1` 念「比」、`常规+加时` 念「加」才对，正则分不出来 → 这类回库里重问，清单在 `console/待重灌.2026-10-01.txt`，82 条） |

   还有两条保命的：超 80 字**退回上一个完整句子边界**（不硬切），`《` 没配上 `》`、`（` 没配上 `）` 就退到括号之前（否则念个「左括号」就没了下文）。
   ⚠️ 注意第二组：`- ` 列表行是**整行丢弃**的，所以"分点答"的模型输出会被削得很短。这是有意的取舍，不是 bug。
5. **两道不入库的门**（后来加的，2026-10-01 09:4x）：`_clock_answer()` 认得出「今天/今晚/此刻/现在/今日」且不带「明天/下周/去年」的句子当场算；`_STALE_Q = 天气|气温|多少度|新闻|最新`。`remember()` 一开头就把这两类**一并拒掉**（`targets.py:485`）—— 答案库是存死的，天气存一次错一天，日历存一次错一年。同一天顺手从库里删了 5 条这种过期答案（481 → 476，就是仓库这份快照的条数）。
   另外 `remember()` 还会拒：`_plain()` 之后什么都不剩（纯链接）、整条不到 30 字且以问号结尾且带反问词。写入是 `{**kb, q: clean}` → 同目录 `.tmp` → `os.replace`，成功后才更新进程内的 `_kb`；读侧按 **mtime** 判断要不要重读（`_load_kb()`），所以别的脚本往库里补货不用重启服务。
   ⚠️ 运维红线：进程内那份 `_kb` 是缓存并**整档覆盖**的。手改 `answers.json` 之后不重启，下一条豆包回答会把你删掉的脏条目写回去。

一句提醒：线上库一直在长（并行会话、真机问出来的都往同一份里追加），**别拿仓库这份 476 条整档覆盖盒子那份**，也别 `rsync` 整个 `genie/` 目录。

## 6. 小爱那条腿（`xiaoai/`）

反直觉但最要紧的一点：**我们从来不推音频给音箱，只推一条 URL，音箱自己去抓。**

小米云那条 ubus 是 `api2.mina.mi.com/remote/ubus`，`mediaplayer / player_play_url`，命令里只有一个字符串。由此推出四件事：

1. `VOICE_BASE_URL` **不能写 `127.0.0.1` / `localhost`** —— 那是音箱自己去连的地址，写回环就是让它连自己。症状极其难查：小爱一句话也不说，node 日志里一切正常（`migpt.env.example:20-22` 的注释就是给这条立的）。所以填**局域网 IP**：`http://192.168.5.42:7790`。
2. 抓 URL 发不了 header → 凭据只能挂在 URL 上；但绝不能挂主 key（引擎会把播的 URL 打进日志）。用派生 token：`hmac(bridge.key, 资源路径)[:32]`，只认那一条音频。
3. **一个 `&` 都不许出现**：实测小米云会把 `&` 变成空格再发给音箱（`/v1/play?url=…%20max_height=480&t=…` → 签名对不上，两次 401）。所以 token 走**路径段** `/t/<hex>`，query 只留一个参数（`ask.mjs:91-102`、`config.js:81-86`）。值的编码还得和 Python 的 `quote(safe='')` 逐字节一致 —— 于是 `encodeURIComponent` 之上再补逃 `!'()*`。
4. 命令回 `code 0` 只代表发出去了，真出声要 `getStatus().status == "playing"`（`ask.mjs watch()`），别拿"命令成功"当结论。

链路上的其他几件事：

- **入口不是麦克风也不是局域网发现**：MiGPT 是**轮询小米云的对话历史**拿"用户说了什么"。所以唤醒只能靠人嘴；`ask.mjs` 的 `/ask` 只是"假装音箱刚听到这句话"（直接调 `engine.onMessage`），心跳照旧在跑，人和这条口子可以同时用（唯一竞争是 `lastMsg`，后到的会丢掉先到的回答，这是引擎本来的行为）。
- **白名单（NATIVE 不接管）**：`config.js:256` 那张表（播放、放歌、来一首、大点声、音量、静音、关机、暂停、停止、下一首…）按**开头**匹配，命中就 `return {handled:true}`，**连静音窗口都不开** —— 因为一接管就得先压它的音量再打断它，那条原生指令反而做不成。词表可用 `NATIVE_WORDS=` 扩。
- **唯一必须抢下来的说法**：带「电视/屏幕」字样的停（`SCREEN_STOP`）。小爱自己的"暂停"只管它自己那份音频，**掐不掉 HDMI 上的画面**，只有我们能杀那个 `gst_play` 子进程。
- **`muteWindow`**：小爱自己那一份答案（COIN）压不住，也不存在"只应答不作答"的开关。所以检测到就 `player_set_volume 0`（`MiNA.setVolume` 被上游 clamp 在 6..100，要 0 得绕过它直发 ubus）+ 两次 `stop`，45 s 守卫兜底，绝不把音箱永久留在静音。`MUTE_COIN=0` 就整段关掉（`migpt.env.example` 给的是 0，代码默认是 1 —— 想两条答案不打架就设 1）。
- **出口三选一**（`config.js:386-396`）：有豆包语音 → `{url}`（不再让小爱自己念一遍）；只有文本 → `{text}`；**整句就是一条链接** → 改说人话（「给你投放视频了，在电视上看。」），否则小爱会把 `https 冒号 斜杠 斜杠 w w w 点` 一个个字母念完。
- **出屏是异步的**，不占音箱那份答案的时间；且刻意**不追问第二句要链接**（那是往你的大模型账号里塞指令，账号比功能贵）。默认也不发任何 persona（`SYSTEM_PROMPT` 留空）。
- 解链失败现在能分清：`core_dep` = 这条片子只在 app 内可看（和片子年龄强相关，新片基本解得出），`没 bit_rate` = 图文 note，那种不收，硬拉播放器只会留一个黑屏。RK322x 只能吃 540 档 —— 1080 档连硬解都追不上（实测整片 352 秒、跑了 8 分钟没完）。

## 7. Mac 侧曾经的角色，和「本地网络」这个坑

Mac 在这套里待过三个角色：① MiGPT 触发器（launchd `cn.qoder.migpt-phone`，代码 `~/opt/migpt-phone`，`7799` 开在 Mac）；② 大模型门 `192.168.5.132:7790`；③ 出屏的落点在红米 5 Plus 的 `playerd`。现在这三个都收了，Mac 只剩**开发机 + 一只耳朵**。

那只耳朵是完整的一截：能量断句（VAD 参数在 `listen.py:29-34`：50 ms 一块、前面留 0.4 s、静音 1.2 s 算说完）→ whisper.cpp 转写 → `route()` 认本地唤醒词（`LISTEN_WAKE`，默认「小松鼠」）→ `_post()` 把唤醒词后面那半句**原话** POST 给盒子 `/local`（`LISTEN_BOX`，默认 `http://<盒子IP>:8092/local`）→ 盒子回 json、Mac 用 `say -v Tingting` 念出来。另外它还写 `~/.genie/听到.txt` 并开一个 `:8091` 让你 `curl localhost:8091` 看最近几句（那个页面滞后 40 秒以上，**不能拿来当「设备开口了没有」的门**，见 05 E9）。盒子那一头是 `genied.py:332-351 local()`：没有平台替你念，所以该念的话放在 json 的 `念` 字段回给 Mac，`greet` 回空串（「您说。」那种开麦用语本地耳朵不需要）。整链实测（2026-09-29 09:0x）：「小松鼠，影子为什么会跟着我」→ 1 秒内念「我查一下啊。」→ 48 秒后电视念出答案。唤醒词「小松鼠」是**本地词**，故意不和「天猫精灵 / 花生同学 / 松鼠同学」撞，各管各的。

那个坑长这样：**launchd 起的 node 连 `192.168.5.x` 一律 `connect EHOSTUNREACH`，而同一台机器上 curl / nc / ssh 全都正常。** 区别只在 launchd 的 node 没有已授权宿主进程 → 被 macOS「本地网络」隐私权限拦死。从 Terminal / IDE 里手起的 node 继承宿主授权，所以能连 —— 这就是「上一轮还好用，这一轮全 401 / 一直说没听清」的真因，跟大模型登录态、密钥都没关系。

当时的绕法（现在不用了，但值得知道）：

```
run-migpt.sh:  /usr/bin/ssh -L 17790:127.0.0.1:7790 -L 17791:127.0.0.1:7791 root@<手机>
               node 只碰 127.0.0.1；手机侧 sshd_config 的 AllowTcpForwarding 从 pmOS 默认 no 改 yes
env 分两套：   自己发请求 → http://127.0.0.1:17790/v1 ；   给音箱抓 → VOICE_BASE_URL=http://<局域网IP>:7790
更省事的解法： 系统设置 › 隐私与安全性 › 本地网络 里给 node 二进制勾授权
```

为什么最终把触发器留在盒子（2026-10-01 11:1x 定的）：

1. **门牌指着停着的机器**：Mac 那份 `LLM_BASE_URL=127.0.0.1:17790` 只由那条 ssh 隧道提供，NAS 一停 → 17790/17791/17792 全关，每次问都连不上，小爱只能说兜底话。
2. **双开必打架**：Mac 和盒子两份 MiGPT 轮询同一台音箱，`lastMsg` 互相挤掉 —— 所谓「时好时坏」的真因就是它。判双开：`pgrep -fl "ask.mjs --serve"`（Mac）+ `systemctl is-active migpt`（盒子），两边同时为真就是双开。
3. **Mac 会打盹**：这台 Mac 的 AC 设置是 `sleep 1`（1 分钟），得用 `caffeinate -i` 包住 node 才有人轮询小米云。音箱链不该依赖一台会睡的笔记本。
4. **盒子一台全包了**：node 22、mpv、chromium、cpolar 都在，`7790`/`9090` 就在本机，HDMI 直连电视。停 Mac 那份用的是 `launchctl bootout` + `launchctl disable`（plist 没删，`launchctl enable` 能复原）。

## 9. 照着搭之前先扫一眼：几处过期说法

- `8092` 是 unit 给的，`genied.py` 里 `GENIE_PORT` **默认 8090**；`LLM_URL` 默认 `http://127.0.0.1:7790/v1`；`GENIE_OFFLINE_DIR` 默认空。不带 env 手跑 `python3 genied.py`，得到的是一个监听 **8090**（不是 8092）、**答案库永远查不中**（`offline_answer()` 恒空）、慢路径永远写不进库（`remember()` 静默返回空串）的实例。手工验功能就 `GENIE_DATA=/var/lib/genie42 GENIE_OFFLINE_DIR=/var/lib/genie42/offline` 起。
- 「第二句不用带调用词」不是 NLU 变松，是**技能会话没散**：`skillSessionId` 全程同一个、`newSession:false`，我们回 `ASK_INF`/`SELECT` 让麦一直悬着。第一次进技能必须有调用词。会话过期就变成平台自己那句「您想问什么?」，一个字节都不给你。
- 别把通用问法（「你能干什么」「有什么好看的」）当唯一入口：这类大白话会被天猫官方技能当场抢走并出声（实测 2026-09-30 07:0x，方糖回的是酷狗会员广告），网页在线测试是技能作用域的、通不算数。**真机通的是「讲讲X」这一族**。
- 判「链路坏了」之前先看 ASR：`say` 合成音十次有三次被听歪（花生同学→花生童学、企鹅→起鹅、北极熊→被指雄），整句匹配不做同音。我用 `/tmp/kx_asr_filter.sh` 筛过 20 条菜名，只有 6 条能被完整说中（青蛙/鹦鹉/长颈鹿/冷笑话/四面楚歌/脑筋急转弯）。
