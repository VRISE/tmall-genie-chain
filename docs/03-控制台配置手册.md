### 1.1 服务部署那个认证文件的坑（最容易卡住半天）

保存「服务部署 / 后端服务」里的 URL 时，**阿里后端会真的向你填的地址发一次 GET**，路径是：

```
GET https://<CPOLAR_域名>/aligenie/<md5(技能id)>.txt
```

内容必须和平台"下载认证文件"按钮给的那份**逐字节一致**才放行。几个必须知道的细节：

- 文件名就是 `md5(技能id)`，前缀可在控制台核对：`md5(120248)=5f1b8e3b…`、`md5(113665)=a7b36227…`、`md5(120282)=aad1e003…`（2026-09-30）。
- 我们这边不用写任何逻辑：`genied.py:370` 的 `do_GET` 里，凡是 `/aligenie/xxx.txt` 就直接从 `GENIE_VERIFY`（默认 `/etc/genie/aligenie/`）原样吐出，并打一行 `← GET … 认证文件 给了/本地没有`。
- **判断"平台来没来过"只能看这行新日志**，genied 只在未匹配时才 log，别的 GET 不会留下痕迹（2026-09-30）。
- HTTPS 还要求证书有效，否则报"无法访问或访问被拒绝"（2026-09-27 读文档）。
- 认证 token 前 42 个字符全账号相同、后 22 位每技能不同，**推不出来**，只能从"下载认证文件"按钮拿（2026-09-30）。
- **换穿透域名时必须回控制台重存服务地址**，否则域名校验失败、意图保存被 `3010 未正确获取到认证文件` 挡回（2026-09-30）。保活三步（2026-09-30 实测）：
  1. 从盒子 cpolar 日志尾取现域名；
  2. `curl https://<CPOLAR_域名>/aligenie/<md5(id)>.txt` 要 200；
  3. 意图 PUT 回写 `webhook.url`，`retCode:0` 就说明平台又取到了一次认证文件。
- cpolar free **给不了固定域名**：`-subdomain=xxx` 会被服务端回 `StatusCode 4003 授权失败，用户当前 Plan 不允许使用该功能`（2026-09-30）。所以别指望"配一次就不动"，把上面三步当成例行动作。

**结论：个人技能那条路是死的，别在上面配后端。** 新技能要跑后端只能建"自定义"类型，然后把它自己那份 `md5(技能id).txt` 放进 `GENIE_VERIFY` 目录（2026-09-30）。

## 2. 意图设计：为什么最后只剩一个意图

### 2.1 形状（2026-09-28 定型，113665 / 120248 都是这个形状）

- 每个技能**只留一个意图**，并且把它设成**默认意图** + **动态意图（`isDynamic:true`）**。113665 的 `welcome` 意图已被删掉，`play_video`（190791）是列表里唯一一行、`意图种类=默认意图`；120248 同理（`zhubajie`/199486）。
- **为什么要收成一个**：
  1. 未命中语料的句子会"跳出技能"（官方《配置语料》原文），兜底只有默认意图这一条路（2026-09-27 读文档，2026-09-29 08:4x 空默认意图真机验证）；
  2. 平台那一侧的多意图 NLU 只会给你二选一，选错的代价比"我们自己判"高得多；收成一个之后 **`intentName` 不再携带信息，区分播放/问答/遥控全交给我们后端**（2026-09-28 09:5x 那次收口之后，`/aligenie/corpus` 只会收到 `intentName=play_video`，服务端 `DEFAULT_INTENTS` 只是历史兼容）；
  3. 官方《创建意图》要求每个共有技能**必须**有一个默认意图，所以删旧默认意图之后**必须立刻**把新意图设成默认，别中途收工（2026-09-28）。
- **动态意图（`isDynamic`）决定平台调不调我们的 webhook**：关掉时平台自己应答（`意图/welcome` + 固定文案），服务端一条请求都收不到；点开同一句话立刻 POST 全量报文（2026-09-28 凌晨，113665 实测）。排查"匹配上了但没调后端"先看这一列，别怀疑穿透。
  接口：`POST /api/skill/<SID>/intent/<IID>/toggleDynamic`（列表页那个按钮是独立实时开关，**「提交」不会影响 `isDynamic`**，2026-09-28 22:25 实测）。

### 2.2 `defaultIntent` 与 `executeLogic`：裸 PUT 一次，整链全哑

这是本项目代价最大的一个坑，务必记住：

| 动作 | 结果 |
|---|---|
| `GET /api/skill/<SID>/intent/<IID>` 拿到 `retValue`，改完 `userSays` 原样 `PUT /api/skills/<SID>/intents/<IID>` | **默认意图被抹成非默认**：回读 `type` 从 `{"name":"DEFAULT"}` 变成 `null`，列表页「意图种类」列从"默认意图"变"自定义意图"；真机连裸喊调用词都零 POST（2026-09-29 06:14，改了两条模板文字 → 06:15/06:19/06:41 三轮全哑） |
| 为什么会丢 | `defaultIntent` **是 GET 不返回、UI 存盘时额外塞进 body 的字段**，GET→PUT round-trip 必然丢（2026-09-30 从前端 bundle `/tmp/kxchunks/19.index.js` 读到 UI 的实现）。`type` 字段本身在 PUT 里写不回去，它不是数据字段而是表单开关 |
| 正确 body | `body = GET 的整个 retValue` + **`defaultIntent:true`** + **删掉 `executeLogic`**（UI 就是这么发的；`executeLogic` 里只有 `{id,type:"WEBHOOK",args:[]}`，**服务地址要读 `retValue.webhook.url`**，按 `executeLogic` 取 URL 会取到 `undefined`，2026-09-30） |
| 恢复办法 | 进 `/console/newskill/<SID>/intent/intentForm/<IID>?type=edit`，页面上有一行「设为默认意图」= Fusion `role=switch`；把文本为"否"的那个点开 →「提交」→ 回读 `type` 回到 `{"name":"DEFAULT"}`（2026-09-29 06:5x 实测有效） |
| 提交后的连带副作用 | ① 所有 `userSays` 的 `id` **整批重新分配**；② `executeLogic/webhook` 的 `id` 被重建，但 **`url` 不会变**；③ **语料被从已训练模型里摘掉 → 必须补点一次训练**（2026-09-28 07:2x） |

> 规矩：**能用 UI 就别用裸 PUT**；用了裸 PUT 必须立刻回表单页确认「设为默认意图」还是"是"（2026-09-29）。

### 2.3 参数（槽位）名 ↔ 后端读的字段

平台回传的 `slotEntities[].intentParameterName` 就是你填的**参数名**，可以写中文。后端在 `genie/genielib/plan.py:77` 做映射：

```python
SLOT_ALIAS = {"年级": "grade", "学科": "subject", "话题": "topic", "问题": "query"}
```

| 你在控制台填的参数名 | 关联实体 | 后端落到哪个字段 | 取值来源 |
|---|---|---|---|
| `年级`（或 `grade`） | 年级实体 | `Plan.grade` | `slotEntities[].standardValue`（归一化值，同义词会归一） |
| `学科`（`subject`） | 学科实体 | `Plan.subject` | 同上 |
| `话题`（`topic`） | 话题实体 | `Plan.topic` / `Plan.query` | 同上 |
| `问题`（`query`） | question 实体 | `Plan.query` | 同上 |

要点：

- **参数名带括号也能对上**：后端先 `re.split(r"[(（]", name)[0]` 再查别名表，所以 `话题(必选)` 这种显示名不会打断链路（`plan.py:138`）。英文参数名不在别名表里也能用（会原样当字段名），`请求样例.方案A.json` 用的就是 `grade/subject/topic`。
- **参数一次配好再测，别中途加**：官方 slot 变量页写明"技能更新时新添加的参数，要审核上线后才能在屏显卡片里用"（2026-09-27 读文档，屏显那条**没实测过**）。
- **「必选」和平台追问是耦合的，方向别记反**：平台的追问由"必选参数缺失"触发。`required:false` 时裸喊调用词**平台压根不调后端**，自己把追问语念掉（2026-09-28 14:05 真机定论）。要走"调用词→平台追问→说一句清单里的话"这个两段式，`required` 必须是 `true`。
  120248 的 `问题` = `required:true`（导出可核对）；120282 当年为了排查改成 `false`，**不影响取值**（2026-09-30：`required:false` 时尾句命中实体照样把槽位填上并送过来）。
- 「精灵追问」那个 Switch **在意图 JSON 里没有任何对应字段**：关掉→提交→回读，`parameters` 字节级不变（2026-09-28 14:0x）。它不是链路条件，别再动它。
- 追问语（`prompts`）填一句能当开麦提示的话，如 `["您想问什么？"]`；`replyTemplates` 填 `["@{问题}"]`（导出里就是这个形状）。
- **一句语料里泛化词参数"最好不要超过一个"**（官方文档，2026-09-27）。`语料.csv` 里 `给我看一下@{grade}的@{subject}视频` 是双槽，能用但不是默认风格。

### 2.4 服务地址填哪

`genied.py` 同时接 `POST /` 和 `POST /aligenie/*`，并按**路径最后一段**决定走哪条腿（`genied.py:441`）：

| 填法 | 含义 |
|---|---|
| `https://<CPOLAR_域名>/aligenie/corpus` | 强制走"方案A"（平台已给 `intentName`+`slotEntities`，走 `plan.from_slots`） |
| `https://<CPOLAR_域名>/aligenie/nlu` | 强制走"方案B"（只有原话，走 `plan.from_utterance`） |
| `https://<CPOLAR_域名>/aligenie/webhook` 或域名根 `/` | 按 `intentName` 自动分（不在 `genied.py:34 DEFAULT_INTENTS` 集合里的当方案A） |

本地自测口（都不出屏、不出声，只判路由）：`GET /log`（最近 80 行，**新的在最上面**；`systemctl restart` 会清空）、`GET /health`、`POST /test`（喂一句原话）、`POST /teach`（一批 ≤60 条只灌答案库）。
**注意 `POST /test` 和平台真链路是两条腿**：`/test` 造的是空 `intentName`/空 `slotEntities` → `from_utterance`；平台发的是 `intentName + 槽位[问题]` → `from_slots`，里面多一道 `_search()` 决定要不要放片。拿 `/test` 的统计去说平台的事会算错（2026-09-30 下午）。

响应硬约束：`reply` **一定会被 TTS 念出来**，没有"只回不吭声"；`Content-Type` 给 `text` 会让平台抛 JSON 反序列化异常；`resultType` 只有 `RESULT/ASK_INF/CONFIRM` 三种，开麦要在「授权配置 → 申请技能权限包」里勾「允许通过 Webhook 触发音箱开麦行为」（2026-09-27 文档；2026-09-28 实测**语音交互基础权限含开麦，个人技能默认已生效，不用申请**）。
**这一跳的预算是 1.5~2 秒**：2026-09-29 用"只对某一句硬 sleep"的办法二分出来 —— 1s 播、1.5s 播、2s 不播、3s 不播。所以 `genied.py:29` 现在是 `FAST_BUDGET=1.5`（配置清单里那句"按 2.5 秒设计"已被这条实测取代）。慢答案绝不在这里等。

### 3.1 单实体 1 万值上限（硬顶）

- 撞到过：**120282 的 `问题` 实体 `totalCount:10000` 就是平台的硬顶**（2026-09-30 02:3x，流水账原话"这是平台的硬顶"）。

- **平台写入不去重**：9828 条里有 38 条是完全重复的值；120282 顶格时库里有 169 行重复（2026-09-29 / 09-30）。所以去重必须在客户端做（先拉一遍现值建 Set 再灌）。
- **顶格之后怎么腾位（两种做法都跑过）**：
  1. **删重复行，零损失**：每个重复值只删多余份、留一份，`DELETE /api/skills/120282/entities/101879/entries/<id>` 删 8 条 → 9992 → 再灌 8 个新词 → 10000（2026-10-01）。
  2. **换类别**：2026-09-30 09:3x~09:5x 那一次，用户说"用音箱念菜谱没意义"，于是**按关键词双匹配删炒菜**（烹饪动词 `做法|怎么做|炒|炖|蒸|煮|卤|凉拌|红烧|糖醋|煎|煲` **且**食材名词同时命中才算，避免误删）：120248 删 **183** 条、120282 删 **154** 条，全 `retCode:0`、0 失败；再灌同一份 **100 词**清单（篮球 21 / 足球 23 / 羽毛球 15 / 三角洲行动 20 / 视频点播类 21），两边各实际灌进 95 条（5 条已存在）→ 新总量 120248=**9755**、120282=**9941**，都还在上限内。复查残留炒菜 0、100 词全在。
     **同步动作别漏**：盒子答案库要同步删 17 条炒菜答案、补 68 条新词答案（100 词里 32 条是点播词不进答案库），库 396 → **464**。删实体不删库 = 同一主题留着念不出的旧答案。

### 3.2 `sys.other`（泛匹配实体）：查到了，但语音技能走不到

- 它**真实存在**，接口里就能看到：`GET /api/skill/public/entities?skillId=120248&keyword=other&pageSize=20&pageNum=1` —— **带上 `sites=open` 就 `totalCount:0`，去掉这个参数就多一条**：`id:48233, name:"sys.other", nameCn:"泛匹配实体", sites:["admin"], scope:SYSTEM, resolution:DICTIONARY`，描述原文写着"**（开发中，请勿使用）** 该实体可以匹配任意长度的字符串…本实体主要用于**多轮和带屏技能**"（2026-09-29 11:0x）。
- UI 两处都复核过，**走界面 100% 到不了**：① 「引用公共实体」那个整页路由发的是 `…&keyword=…&sites=open`，搜"泛匹配"列表纹丝不动；② 意图 → 参数 → 关联实体下拉**只列技能自己的实体**，公共实体必须先引用进来才会出现。
- **直接把 `parameters[0].entityId` 改成 48233 强行绑上：没做、没测过。** 素材里明确记着"动他线上技能前要先确认"，而且它自己写着"请勿使用 + 系统方会对其匹配到的语料做管控"。
- 语音技能能用的泛化口子只有 **`sys.select` + `Dialog.SelectSlot`**（值由服务端每轮下发）；公共实体总共 **25 条 / 3 页**（`sys.time/datetime/location/anyNumber/…`，**没有任何自由文本类**）（2026-09-29）。

### 3.3 `resolution` / `scope` 该填什么

| 字段 | 填什么 | 填错会怎样 |
|---|---|---|
| `scope` | 字符串 `"DOMAIN"`（技能私有实体）；平台公共实体是 `"SYSTEM"` | 传对象 `{name:'DOMAIN'}` → `5000 parse enum EntityScope error`。**必须是字符串枚举**（2026-09-30 02:0x） |

### 3.5 词条写法（念不出来的一律别灌）

`console/待重灌.2026-10-01.txt` 就是踩完坑列出来的复检表，82 条、一行一句 + 原因：**英文字母 40 / 撞 80 字上限 18 / `+` 号歧义 10 / 比分写法 4 / 算式串行 3**（一条可以多标，如 `三角洲行动怎么当狙击手=英文字母`、`上一届世界杯冠军是谁=加号歧义、比分/区间歧义`）。配套规矩：

- 词条**别带英文字母和数字**：ASR 会把数字念成中文、英文缩写（NBA/MVC/3D）清不干净（2026-09-27 配置清单 + 2026-10-01 待重灌）。

- **喂裸名词（葫芦娃、猪猪侠）大模型十次有十次只甩一条视频链接、不给话**，要用"讲讲X"这种完整句式（2026-09-29）。

## 4. 语料：模板和整句是两件事

### 4.1 两种类型（字段 `type`/`typeUI` 才是真身份）

| 写法 | 存进去的 `type` | 平台怎么匹配 | 注意 |
|---|---|---|---|
| **模板式** `给我看一下@{年级}的@{学科}视频`、`播放[话题]的MV` | `"TEMPLATE"` | 槽位由实体词表填，`slotEntities` 带回 `standardValue` | **必须先把参数建出来**；`@{}` 里的名字要对上参数名。UI 里「例句/模板」下拉**刷新就退回"例句"**，它不是每行的属性（2026-09-28） |
| **例句式 / 整句** `帮助`、`能放动画片吗`、`红烧肉怎么做` | `"SAMPLE"` | **整句完全匹配**才命中，**`slotEntities` 是空的** | 例句模式下输入含 `@{}` 的串会被**静默拒绝**（框清空、计数不变、无报错）（2026-09-28 22:25） |

**为什么「帮助 / 你是谁 / 能放动画片吗 / 你可以帮我干什么 / 讲故事 / 听歌 / 放首歌」这类必须写整句**：这类句子**根本没有槽位可走** —— "帮助"两个字里没有任何实体值，"能放动画片吗"的动词壳（能不能/放/吗）不是参数。平台只能靠 literal 命中。113665 就是这么补的 12 条整句（2026-09-29 晚间，`PUT /api/skills/113665/intents/190791` 200 + 训练 200，意图语料总数 48）。
反过来，整句命中时后端拿不到槽位，`plan.py` 用 `_tidy()` 从原话里抠出"要放的东西"（剥 `吗呢啊吧` + `能不能/可以/帮我/给我/我想` + 开头的 `放/看`）；**没这一层，音箱会念"这就放天天同学，动画片"**（2026-09-29 流水账第 11 条）。

### 4.2 一条裸 `[话题]` 为什么反而危险

- **事实**：113665 的 48 条语料里**没有一条是裸 `[话题]`**，全是带动词壳的（`播放[话题]`、`[话题]的动画片`、`讲讲@{话题}`、`@{话题}怎么做`）。所以"灌再多话题也必须配上对应句式"——**实体值只透过已有句式命中**（2026-09-29 晚）。
- **UI 层面它打不进去**：语料框**拒收 `[` 和 `]`**，而切换「例句/模板」的下拉不在无障碍树里（2026-09-29 晚）。
- **为什么"危险"（这段是推断，没实测过）**：一旦真配上裸 `[话题]`，整个实体词表都会命中同一个意图 —— 而 120248/113665 的实体里灌的是**混装**的（`红烧肉怎么做`、`你能干什么` 这类提问也在词表里）。裸模板会把提问类句子按"点播"送进后端，`plan.py:180` 那条 `intent not in PLAY_INTENTS` 的兜底也拦不住带槽的情况。**113665/120248 都没有配过裸 `[话题]`，所以这条行为的真实后果没人验过。** 稳妥做法就是素材里这套：**每个句式自带动词，别写裸槽位**。

### 4.3 语料框的三个怪癖

1. **不按空格分行**：`帮助 你是谁` 会被当成**一整条**语料存进去。这条垃圾 2026-09-29 晚留在 113665 的 48 条里，**至今没删**（删一行的 `×` 要 hover 才出现、不在无障碍树里，不值得冒险）。实体值框正相反，**按空格分条**，一次回车最多 20 条 —— **两个框规则不一样，踩反了会以为没加上**。
2. **例句/模板下拉**默认"例句"，选错模式时 `@{学科}` 就是字面字符 → 永远不命中（2026-09-28）。
3. **「用户可能回复」那一栏只能填模板式语料**（2026-09-27 读文档，UI 层面**没实测过**）。

### 4.4 文件导入：格式坑 + 死路

- **导入模板不是 CSV**：控制台"下载文件模板"给的是 **GBK 编码、分号分隔、首行 `"dialog";"参数名1";"参数名2"`**，语料里用 `@{参数名}` 占位。仓库里 `console/语料.导入.csv`、`语料.补充.csv`、`话题.补充.csv` 就是按这个格式生成的（`file` 认成 ISO-8859，**别用 UTF-8 打开编辑**，会存成乱码）。
- `console/语料.csv` 是 UTF-8 逗号分隔的**清单文件**（给人看的），和导入格式不是一回事 —— 配置清单 §3 写"批量导入用语料.csv"这句**和 09-28 的实测冲突**，按 GBK 那份走。
- `console/语料.自动.csv` 是 `gen_corpus.py` 展开的穷举版（12 个动词架子 × 年级×学科 × 4 个中段 × 6 个尾巴 + 话题×架子 + 18 条控制句）：**88458 句**。别往控制台传（超出实体上限，且模板式已经覆盖同样组合）。`gen_questions.py` 是另一条：名词族（做菜/知识/怎么学/在哪里/有多少/动画人物/动物/身体/学校/节日/玩具/科学事实）× 疑问句式，产出整句清单灌 `question` 实体。`--check` 会报重复句和"多槽又超长(>24 字)"的可疑句。
`console/挑待灌.py` 是配套的选择器，但**它挑的是要喂进"盒子答案库"的那一批（读 `/tmp/ans42-dump.json` 现库 + `/tmp/qvals.json` 实体全量），不是控制台语料**：它照抄后端答案库的命中判据（`norm(y)==norm(k)` 或 `core(y)==core(k)`，或 `len(k)>=5` 且两句互为子串），按**边际增益贪心**选 20 条 —— 一条答案能顶几句是可算的，别把大模型额度浪费在同一主题的第二句上；不够 20 条时按 `是谁/的故事/吃什么/为什么/怎么做/在哪里/有什么/怎么办/的由来` 这几个高频句式补（这段没标日期）。喂库走 `POST /teach`，**一次最多收 60 条**（`genied.py:457`）。
- **死路的原因**（2026-09-28 ~ 09-29 反复撞）：原生文件 picker **不在无障碍树里**；`upload_file` 对 `<input type=file>` 永远报 `Invalid arguments for file_upload: name is not supported`；`press_key` 只吃 ASCII、Cmd+V 无效；`evaluate_script` 时好时坏（09-29 晚间一律返回 `{}`）。**所以批量灌值别走文件导入，走接口。**

### 6.1 路 A：控制台 UI（量小、想留痕时用）

另外三条 UI 硬钉子，别浪费时间：**「必选」勾选框点不动**（不在交互树里，点它所在格子会把坐标算到表头，只能人手点，2026-09-28 14:0x）；**「添加测试设备」弹窗的验证码框能聚焦但吃不到字符**（`press_key`、`Meta+v` 都不进字 —— 但 §7 里有绕开的办法）；意图编辑页一旦"脏"，之后每次点击都会先弹一个原生 `confirm(目前正在编辑状态…)`，会把浏览器连接器整个卡死，解法是重载那个标签页（2026-09-28）。

### 6.2 路 B：同源 `fetch` 批量灌（量大时用这个）

**认证只有一个坑**：所有 `/api/...` 带 `credentials:'include'`，**POST/PUT/DELETE 必须加头 `x-csrf-token: <cookie 里 ctoken 的值>`**，否则 nginx 直接回 `<h2>403 Forbidden</h2>`。`_tb_token_`、`x-xsrf-token`、只放 query 参数**全都无效**（2026-09-30 实测）。ctoken 从 `document.cookie` 取（`console/灌值.js:14`），URL 上也带一份 `?ctoken=<同一个值>`。

请求形状（2026-09-30 02:0x~02:3x 一次跑通，逐条实测）：

| 动作 | 请求 | 坑 |
|---|---|---|
| 列意图 | `GET /api/skill/<SID>/intents?pageNum=1&pageSize=200` | **分页参数叫 `pageNum`**；`pageIndex/page/curPage` 一律 `3010 页码必须从1开始`。不带分页直接 `3010 参数错误,单页记录数无效`。返回是**双层** `retValue.retValue.result` |
| 读意图 | `GET /api/skill/<SID>/intent/<IID>` | 路径是 **skillId 不是 domainId**（填 96124 会 `4000 技能不存在`）；`/intents/<IID>` 是 404 |
| 存意图 | `PUT /api/skills/<SID>/intents/<IID>` | 见 §2.2（`defaultIntent:true` + 删 `executeLogic`） |
| 列实体 | `GET /api/skills/<SID>/entities?pageNo=1&pageSize=50` | 路径复数；这里才是 `pageNo` |
| 列实体值 | `GET /api/skills/<SID>/entities/<EID>/entries?pageIndex=1&pageSize=100&query=` | **entries 的分页叫 `pageIndex`**（2026-09-30 02:3x 明确纠正过一次：按 `total/result` 读成空，会误以为 10000 条被抹掉）；响应字段 `totalCount/pageCount/result`，值在 `normValue`。同一接口用 `pageNum`/`pageNo` 也读到过数据（09-28/09-29 记录），**哪个是唯一正确写法素材里打架，见文末** |
| 灌**一个**实体值 | `POST /api/skills/<SID>/entities/<EID>/entries`，body **单个对象** `{normValue:"…", synonyms:[]}` | **传数组 → `syntax error, expect {`；传 `{entries:[…]}` → TDDL/MySQL 异常**。一条一个 POST |
| 改同义词 | `PUT` 同 URL，body `{id, entityId, normValue, synonyms:[…]}` | `normValue` 不带会被清掉；PUT 不校验字段名（写错也回 `true`） |
| 删实体值 | `DELETE /api/skills/<SID>/entities/<EID>/entries/<id>` | 条目 id 从列 entries 的 `result[].id` 拿 |
| 训练 | `POST /api/corpus/skills/<SID>/update/model`，body `{itemId:<SID>, intentId:<IID>}` | 见 §6.3 |
| 在线测试 | `POST /api/tools/test`，body `{skillId, query, sessionId, extendInfo:{}}` | 见 §6.4 |
| 技能信息 | `GET /api/skill/ext?id=<SID>` | 有 `invocationName`、`executeLogicSetId`、`trainStatus`（**这个字段一直是 `NEW`，不能当训练进度用**，2026-09-30） |
| 提交审核 | `POST /api/skills/<id>/operate` body `{type:"COMMIT_AUDIT"}` | **别点**，自用不需要审核 |

`console/灌值.js` 就是这套的成品，粘进 F12 直接用：`__loadHave()` 分页拉现值建 Set 去重 → `__push([...])` 或 `__pushX(名词, 句式)`（`{a}` 占位，一次生成一批）排队 → `__runQ()` 起 6 路并发 → `__stat()` 看进度。`console/灌值_两只小狗.js` 是"灌值 + 顺带 PUT 同义词"的一次性脚本（有的版本 POST 不吃 `synonyms`，它就先 POST 拿 id 再 PUT 补上）。
**页面刷新会把这些函数丢掉**，要重建（2026-09-28）。

**8277 条那套配方（2026-09-29 16:2x~16:4x，142 秒 / 8158 个 POST / 0 失败）**：

1. Mac 本机起一个只绑 `127.0.0.1:8099` 的小 HTTP 服务（`/tmp/kx_serve.py`），回 `Access-Control-Allow-Origin: *` + `Access-Control-Allow-Private-Network: true` + OPTIONS 204；
2. 让 HTTPS 页面 `fetch('http://127.0.0.1:8099/kx_all.txt')` 一次把 196 KB 整包拿走（HTTPS 页面打 localhost **不算 mixed content**，这条路是通的）；
3. **先在页面里 `crypto.subtle` 算 SHA-256 跟本地对一下再开写**（这次对的是 `de9f5661…`）；
4. 起 5 个 worker 并发 POST，跑完 `pkill -f kx_serve.py`。
   反面教训：**别把清单编码成 gzip+base64 分三段贴进控制台** —— 这次三段字符数、结尾都对，但三段 SHA 全错（抄错字，浏览器解压报 `invalid distance too far back`）。随机串抄写不可信，中文整句才抄得动。

**为什么不用 JS 点复选框**：素材里**这条路没有成功记录**（没测过）。原因是那批控件（`例句/模板` 下拉、批量导入 picker、必选勾选框、验证码输入框）都不在无障碍树里，而 `evaluate_script` 在 09-29 晚间一度"连 `()=>document.title` 都只回 `{}`"；09-30 又摸清它其实**要传自调用表达式** `(async function(){ … return JSON.stringify(x); })()` 才有序列化返回值。结论：**要写数据就直接同源 fetch，别去模拟点选**；单次脚本控制在 ~10 秒内、轮询拆多次调用，否则 harness 报 "side-effect outcome could not be confirmed"。还有个陷阱：`list_pages` 每次调用会新建一个 `about:blank` 幽灵页，`evaluate_script` 会跑在幽灵页上 —— 每次 evaluate 前若调过 `list_pages`/`select_page`，要先 `navigate_page` 回目标页（2026-09-30）。**`evaluate_script` 跑在隔离世界**，hook `window.fetch`/`XMLHttpRequest` 抓不到页面自己的请求，别在这上面耗时间（2026-09-28）。

### 6.3 训练：必须 POST 才算生效

```
POST /api/corpus/skills/<SID>/update/model
Content-Type: application/json   x-csrf-token: <ctoken>
body: {"itemId":<SID>,"intentId":<IID>}     → {"retCode":0}
```

- 这就是 UI「语音交互模型训练」按钮那一条请求（toast 是"触发成功."，**没有任何进度**）。
- URL 形状别改：`/api/corpus/skills/<SID>/199486/update/model` 和 `/api/corpus/<SID>/...` **都是 404**；`itemId` 是路由里那个 skillId（2026-09-30）。
- **`retCode:0` 只代表排上队**，生效仍要几十分钟（09-30）。但**"等 30~40 分钟"这条不要当硬指标**：素材里明确承认过"我从来没有任何证据证明有个训练队列在跑，状态接口全 404，那是我从在线测试表现倒推的猜测"（2026-09-29 07:1x）。**唯一可信的终点是"后端有没有收到那条 POST"**：盒子 `curl -s localhost:8092/log`。
- 想要一个可观测探针：原样再点一次「提交」，看 `PUT /api/skills/<SID>/intents/<IID>` 的状态码 —— **403 = 还在训练（训练期锁编辑），200 = 训练已完**。注意这次点击本身又把语料摘出模型了，点完要补一次训练；**只在等满 30 分钟以后才用这个探针**（2026-09-28 07:2x）。
- **哪些动作会弄坏已训练模型**：① 任何一次「提交/PUT 意图」；② **整份实体被重写或删除之后**。后者是 2026-09-29 夜抓到的"整条链零 POST 的头号原因"（120248 的 `question` 被另一会话 1410→1507 重写后，清单内的句子也全部 `意图/null`、零 POST；补点训练后几分钟内重新有 POST）。
  **它否掉了 09-28 那条"灌实体值不用点训练、立即生效"** —— 灌**新值**可能立刻能用，但整份大改不训练就会全哑。**规矩统一成：改完就点训练。**
- 训练期间所有匹配都返回 `意图/null`，看起来像语料坏了；**两个会话并行点训练会把等待时间叠加**，动手前先看后端日志最近有没有真请求（2026-09-28）。

### 6.4 在线测试：能批量回归，但有两道门槛
